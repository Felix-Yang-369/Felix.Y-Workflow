# Skill 行为验收案例

发布前用以下输入和上下文对照规则审阅；需要实际模型验证时，在新会话先用虚拟页面/图片说明进行无写入演练，只有用户明确授权才对真实页面写入。逐条记录观察结果，不把静态关键词命中报告为行为通过。

| 场景与输入 | 预期 | 不应出现 |
|---|---|---|
| 已提供学科页面：“优化方案展示一下” | 给出具体修改稿或相关完整提纲，只读 | 改动页面或只列抽象原则 |
| 已有方案：“章节命名不要改，其他执行” | 保留章节名并实施其余已授权项 | 重问已明确的授权、改章节名 |
| 已排除第七章：“开始” | 执行最近方案并持续排除第七章 | 恢复被排除章节 |
| “完善内容” | 在当前章节下补必要知识 | 默认移动页面、重建数据库或生成封面 |
| 学科页：“INTRO 不算序号” | 简介仍为 H1 但无章号，正文从 I 连续编号 | 降低简介层级或更改章节名 |
| 只改一个定义段落 | 局部修订 | 顺手重编号全篇历史标题 |
| 学科页新增或整理“学科联系” | 在相关正文右侧使用 Toggle List，加粗双语折叠标签，展开后保留关联说明与原生页面引用 | 放在左侧或双栏外作为编号章节、用 Toggle Heading 替代、丢失链接 |
| 只要求更新“学科联系”技能规则 | 更新技能与格式指南，保留现有未提交改动 | 自动改动当前或其他历史 Notion 页面 |
| 学科页：“整理双栏”，现有 H1 在左栏 | H1 移到双栏外独立整行，保留名称、编号和颜色；H2 至第五层按长度灵活安排 | H1 留在左栏、把第五层改成标题、强制每个 H2 单独成对 |
| 左右长度相差约 4 行，辅助内容与同章邻近正文相关 | 保持可读布局，接受约 5 行视觉宽限；允许有标签的适度错位 | 插入空白或无关文字凑等高、强制逐条对应、借另一章内容补齐 |
| 长例子令右侧明显超出左侧，未提供渲染视图 | 在完整内容边界调整双栏，只报告长度估算；图表高度也需考虑 | 按 Markdown 换行数声称精确对齐、拆碎例子、缩字号或删知识 |
| 学科笔记新增 flowchart，编辑器支持显示模式 | 只展示 Display 渲染图，并核对节点、箭头、标签；正文、右栏和 callout 不重复源码 | Code 视图、图与源码并排、回复中再次贴图代码 |
| 既有 Mermaid 图位于 callout、折叠或嵌套块，本次获授权整理显示 | 检查所有这些位置并切换 Display；保留图内容和有效资源 | 只检查顶层、把图源码藏进折叠区当作已隐藏、删除图 |
| 图块接口只支持 Mermaid Markdown，不支持显示模式 | 使用可用 UI 设置 Display 或嵌入渲染图；无法实际核对时说明显示检查未完成 | 臆造显示属性、仅凭 mermaid 语言标记声称只显示图 |
| 笔记同时含状态图、时序图与 HDL 示例 | 图示只展示渲染图，保留讲解程序本身所需的 HDL 代码 | 把所有代码示例都删除、状态图或时序图继续露出源码 |
| 编辑器将 Display 标为 Preview；或整页替换后重建图块 | 选择仅显示预览并隐藏代码；重建后再次核对实际图形与源码隐藏状态 | 只按按钮名称判断、不核对重建后恢复的 Code 或并排模式 |
| 用户明确要求查看图源码；或只要求更新技能 | 前者按该次要求提供源码；后者只更新技能规则 | 忽略明确源码请求、因技能规则变更批量改历史页面 |
| 工作区仅改显示名，ID 与祖先路径匹配 | 继续已授权维护 | 因旧名称不匹配而停工 |
| Softmax 课中：“为什么用 e” | 直接解释底数选择及必要推理 | 重讲整章或强制测验 |
| 注意力计算未完，刚解释子网掩码：“继续主线教学” | 接回注意力计算未完成处 | 继续网络课或假定练习已答对 |
| 没有可识别历史：“继续主线教学” | 询问最小必要起点 | 虚构教学进度 |
| “Transformer 数据怎么流动？然后解释公式动机” | 先流程示意再抽象推导，共用主线 | 两套完整重复课程 |
| 已认可图：“绿色换成紫色，其他不变” | 参考原图局部改色并对比其余部分 | 重做标题、构图或自然材质色 |
| 右侧标题、非电影感、一个主体加三辅助的系列 | 后续同系列沿用认可设定 | 工程模板覆盖成左标题、电影感、五辅助 |
| 用户只要封面预览 | 交付预览，不写 Notion | 擅自替换页面封面 |

## 0.4.14：完整覆盖与持续完成


| 输入或情形 | 预期行为 |
|---|---|
| 优化一篇六章笔记 | 检查六章，处理全部相关缺陷；不是只改第一章 |
| 只完善第一章 | 完成第一章，保留后续章节 |
| 优化方案 | 提供完整范围的具体方案，不写入 |
| 对明确的页面方案回复“执行” | 执行该方案，不重新索要同一授权 |
| 对聊天提纲回复“优化” | 交付一致的改进提纲，不擅自写入 Notion |
| 完善数据库中的所有公司 | 先枚举目标集合，再逐页处理与报告遗漏 |
| 一页写入失败 | 核对真实状态、合理修复，并继续独立页面 |
| API 回读正常但浏览器不可用 | 内容验证与视觉未验证分别报告 |
| 页面已经完整 | 说明检查结果，保留合格内容，不为改而改 |
| 六章方案与七章清单冲突 | 在交付前解决，不将矛盾版本交给用户 |


附加检查：公司默认仍为简短概览；仅正文任务不扩展修改属性；父页正文优化不递归修改子页；已排除章节持续排除；批量范围分页不完整时明确覆盖缺口。

发布检查须区分静态规则审阅、包结构验证与真实会话验证；没有真实会话证据时不得宣称上述行为已经端到端通过。

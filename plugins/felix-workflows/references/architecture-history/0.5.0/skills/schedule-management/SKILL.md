# 日程管理

先读[公共执行规则](../../references/execution-rules.md)，再读取完整的[原日程工作流](references/schedule-management/workflow.md)。所有已有日历分类、命名、来源优先级和验收要求继续适用。

- 进行日历修改前读取[日历规范](references/schedule-management/references/calendar-policy.md)
- 整学期构建、周次、假日与考试调和读取[学期流程](references/schedule-management/references/semester-workflow.md)
- Windows 客户端操作读取[Notion Calendar 流程](references/schedule-management/references/notion-calendar-windows.md)

Apple Calendar 与 Notion Calendar 是同一组 iCloud 数据的客户端，不能用另一个 Notion 数据库替代。按当前工具能力确认真实账户、日历和循环事件范围；先核对已有事件，保留同步等待、例外和去重要求。

“可能漏课”是核查线索；用户最新明确更正按原规则处理。区分一次事件、后续事件和整个循环。删除要求、未知考试信息与界面能力限制均沿用原模块，不因入口重构而放宽。

日程任务只覆盖用户当前明确指定的范围。复习清单与讲解可转读[学习管理](../learning-management/SKILL.md)，不据此自动创建日历或更改定时任务。

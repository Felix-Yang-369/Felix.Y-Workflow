# 公共执行规则

这些规则连接六个入口，先读[Felix 的公共偏好](felix-preferences.md)，详细工作要求仍以入口所选择的完整原模块和用户当前明确指令为准。

1. 先识别任务对象和交付物。查看、分析、方案与实施分开；“开始／执行”承接最近明确且可识别的方案及其对象，已确认的保留和排除项继续有效
2. 只读取完成任务所需的领域入口及具体模块。原模块全文、它要求的格式／来源／完成参考文件均实际读取，不把入口提纲当成完整规范
3. 使用当前真实来源与工具能力。页面、账户、数据库、日历和本地档案各自确认身份、位置和授权范围；真实工具障碍只影响对应事项，其余工作继续推进
4. 修改 Skill 或插件只改变工作流文件，不自动授权任何 Notion、日历、金融或对外操作。本地源文件保存、安装缓存、新会话行为和宿主实际显示是不同层面的结果
5. 承接用户的新要求，不从旧缓存恢复其已保存修改。原模块内部存在会影响当前动作的矛盾时，说明准确位置，保留内容并仅澄清受影响的选择；纯迁移不借机改写业务规范
6. 保留有效内容、资源与用户选择。写入结果不确定时先回读真实状态，再决定是否重试；完成核对不能用提交成功或文件数量代替
7. 原模块约定的结构、内容、数据核对与视觉验收分别报告，未完成项准确标明；新入口不会放宽任何原有要求
8. 使用现有授权、免费或已有订阅资源，不新增费用、收费超额、购买或升级。发布、发送、调度变化和资金交易需要对应的明确用户指令

## 原文与新入口的关系

- `skills/<领域>/SKILL.md` 是当前可发现入口
- 其 `references/<原名称>/workflow.md` 是从原 SKILL.md 完整迁来的可编辑正文；保留原 YAML 和历史用语，它们不再是独立入口
- 原 `agents/openai.yaml` 和素材保留在各原模块目录，记录原有配置；当前六类界面由各领域入口的 `agents/openai.yaml` 控制
- 原文写到旧维护路径或旧 `$skill-name` 时，按[迁移索引](skill-map.md)找到当前入口及模块，不据此写回已迁出的旧目录
- 旧名称对照是文档导航，不声称宿主提供自动别名；用户可直接点名六个新入口

# 创作管理

本入口负责 Felix 面向读者或观众的个人作品。先读[公共执行规则](../../references/execution-rules.md)，按当前平台读取对应的独立 Markdown。

| 作品类型 | 独立模块 |
|---|---|
| 个人博客文章、系列或已有文章维护 | [个人博客](references/personal-blog.md) |
| 抖音短视频作品 | [抖音作品](references/douyin.md) |
| 小红书图文或视频作品 | [小红书作品](references/xiaohongshu.md) |

先识别本次要完成的阶段：选题、素材整理、脚本或文案、制作、发布准备、已发布作品维护或复盘。沿用用户现有作品目录和管理方式，保留作品 ID、采用版本、原稿、素材来源、已发布链接及已有反馈；没有指定时先形成可审阅的稿件，不自建跨平台数据库或定时任务。

只读取涉及的平台；跨平台任务共享事实底稿和采用素材，各自维护表达、版本和发布状态。平台限制、导出规格和工具能力按当前要求核实，不假定所有平台可以自动连接或发布。真实作品与账户资料放在用户指定位置，插件内只保存方法。

草稿、成品文件、发布准备、实际发布和发布后核对分别记录。只有相应发布或修改请求才执行对外操作；核实实际作品、账户和结果后才能报告已发布。用户要求“先别发布”时保留待发布状态。

学科笔记正文、数据库、插图及学科封面由[学科笔记](../academic-notes/SKILL.md)负责；行业与公司笔记、行业封面和公司 Logo 由[行业笔记](../industry-notes/SKILL.md)负责。将笔记改编为平台作品时，按所需范围读取事实底稿与相应模块，不自动修改源笔记，也不加载无关笔记模块。

这轮建立平台分工和可编辑入口，后续可逐个平台细化写作风格、制作规范和复盘指标。原有四类笔记视觉工作流及全部素材已完整归入前两个入口，见[迁移索引](../../references/skill-map.md)。

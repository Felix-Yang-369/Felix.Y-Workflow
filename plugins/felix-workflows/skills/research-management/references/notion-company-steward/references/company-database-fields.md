# 企业数据库字段：现状与建议

以下现状基于 2026-09-25 对科技、消费、工业、金融、医疗、地产等分支 20 个代表企业数据库的字段抽样。未覆盖所有企业库，字段可能继续变化；任何编辑先重新读取目标数据库的数据源结构。

## 实际共性

| 项目 | 抽样覆盖 | 当前表现 |
|---|---:|---|
| 企业名称（标题，不计入普通字段） | 20/20 | 每库恰有一个标题属性，但属性名有 `Name`、`公司`、`汽车巨头`、`芯片巨头`、`运营商`、`快餐巨头`、`律所`、`游戏巨头` 等 |
| 总部 | 19/20 | `总部` 或 `HEADQUARTERS 总部`；通常是文本 |
| 创始人 | 15/20 | `创始人` 或 `FOUNDER 创始人`；医疗器械库使用 Person 属性，其含义需核对 |
| 官网 | 10/20 | `WEBSITE 官网`，URL 属性 |
| 产品 | 10/20 | `产品`、`PRODUCTS 产品`、`代表产品` 或 `代表游戏`，具体语义不同 |
| 领导人 | 8/20 | `领导人` 或 `LEADER 领导人` |
| 成立、所有制 | 各 5/20 | 只在部分库出现；成立字段有文本与数字两种类型 |

行业、领域、品牌、角色、地区、规模、估值、GMV、收入及地位等字段随数据库而变化。`规模` 和 `估值` 不可互换；带数字的字段须核实统计对象、时点、币种与口径。抽样覆盖率只描述现有结构，不表示字段填写完整或内容正确。

## 标题与字段的命名规范

企业名称写在数据库条目的**页面标题**，英文名称全部大写，后接中文名称，例如 `TESLA 特斯拉`。在 Notion 的技术结构中，页面标题由一个 Title 类型属性承载；在本规范的字段清单与字段排序中，**企业名称不算普通字段**。写入现有数据库时，使用该库实际的标题属性名，不因标题展示格式而改名或新建一列。

新建普通字段的名称**只用中文**，例如 `总部`、`官网`；英文全大写加中文的格式仅用于企业页面标题。下面的类型和顺序是新建企业库的建议基线；只按研究目的保留需要的字段。它不表示现有企业库已统一，也不授权自动迁移。现有库按实际属性名和类型写入。

| 显示顺序 | 建议字段名 | Notion 建议类型 | 内容规范 |
|---:|---|---|---|
| 1 | `总部` | 文本 | 国家或地区＋**都市区/通行都市圈**；见下方统一口径 |
| 2 | `创始人` | 文本 | 默认只填最核心的一位创始人的姓名，不与现任领导人混淆；多人难分、机构联合发起或主体特殊时单独审核，保留原值；中国姓名有可核实英文名时采用“英文名 中文姓名”，不自行起名或自动加拼音 |
| 3 | `行业` | 文本 | 主要所属行业，与主要归属页面核对；跨行业业务在正文补充 |
| 4 | `领域` | 多选 | 细分业务领域；选项需在同库内统一，确无筛选需求时可不建此列 |
| 5 | `成立` | 文本 | 成立年份或日期；多次重组时注明所指实体和口径 |
| 6 | `领导人` | 文本 | 现在公司的实际控制人或 CEO，只填姓名；联席 CEO 可并列姓名，不附加职务、日期、来源或其他备注；无法可靠确认时留空 |
| 7 | `所有制` | 单选 | 上市、私有、国有、子公司等；选项口径在同库内统一 |
| 8 | `产品` | 文本 | 主要产品或服务，区分品牌、子公司和产品 |
| 9 | `规模` | 文本 | 默认按估值／市值、营收、利润、人数规模四项填写；口径与缺项规则见下文 |
| 10 | `简介` | 文本 | 一句说明公司做什么及产业链位置 |
| 11 | `称号` | 文本 | 经核实的常用定位，避免无法验证的排名宣传语；这是可选的普通文本字段，不是 Notion 的 Title 类型 |
| 最后 | `官网` | URL | 官方企业主页的完整链接；找不到可靠官网时留空 |

`总部`、`创始人` 分别是**普通字段中的第一项和第二项**；企业名称仍为页面标题，其余字段保持相对次序。填写时按总部所在地所属的都市区归一，而非机械采用注册地、办公楼所在的小城市或郊区名称：旧金山湾区统一写 `美国湾区`；深圳写 `中国深圳`；洛杉矶都市区统一写 `美国洛杉矶`，即使具体地址在尔湾也如此。具体城市、园区或街道确有研究价值时，可在正文补充。`官网` 通常放在**可见普通字段的最底部**，类型始终是 URL，而不是普通文本。

`规模` 默认填写四项：`估值／市值：…；营收：…；利润：…；人数规模：…`。上市公司写可核实日期的市值，私有企业写明确轮次或时点的估值；没有可靠数字写 `待核实`，确实未公开写 `未披露`。营收、利润优先使用同一财年的公司口径，注明币种、年度和净利润或营业利润等具体类型；不同期间不可直接并列比较。人数规模需明确统计对象与日期：社交软件库默认写用户人数，并注明月活、日活、付费用户或注册用户；其他行业按研究目的选用户或员工人数，不混作同一指标。旧值中的市值、估值、月活和注册用户数如无日期或来源，不可直接改写为当前规模。

`上市情况` 不作为默认字段；在已移除该字段的库中不得重新创建。默认不调整 Table View 列宽；即使新值较长，也保留现有列宽，只有用户明确要求才调整。

专用字段另按行业增加：芯片可用产业链角色；汽车可用品牌和主要市场；银行可用银行类型及带币种、报告期的资产规模；游戏可用代表游戏。只有需要筛选、比较或维护时才加字段，不为凑齐模板创建空列。

## 对现有数据库的操作规则

1. 先读取目标数据库和数据源结构，识别实际标题属性、同义字段、字段类型及视图。写入现有条目时按原字段名和原类型操作。
2. `总部` 与 `HEADQUARTERS 总部` 等语义相同的历史字段，优先复用目标库已有字段；单页整理不新建同义列，也不改共享数据库结构。
3. 需要跨库比较时，在分析中建立字段对应关系，并标明缺项和口径差异；不能把缺列当作空值，也不能将文本规模直接与数值估值比较。
4. 只有用户明确要求某个数据库的字段迁移时才制定字段映射、保留旧值与视图设置，并在迁移后核对样本条目和数据库结构。
5. 新增企业条目按母公司记录已被收购公司，将其名称与关系写入母公司字段或正文，不重复新建条目。现有独立子公司页面保留并注明关系，逐一审核后再考虑合并；正文与现有属性补全不授权合并、删除或移动。例如 LinkedIn 记录在 Microsoft 页面中。若该公司后来独立上市、分拆，或用户明确要求单独研究，再单独建条目。

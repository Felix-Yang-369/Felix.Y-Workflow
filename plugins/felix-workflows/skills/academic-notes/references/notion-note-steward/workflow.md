# 学科笔记

主要维护 Felix 的 Notion 学科知识树；工作区显示名可能为 `Felix.Y 的个人空间` 或旧称 `Felix 的笔记本`，使用前仍须验证当前工作区身份。行业分类与研究使用 [行业笔记管家](../../../industry-notes/references/notion-industry-steward/workflow.md)；公司正文、字段、品牌配色和模板使用 [公司笔记管家](../../../industry-notes/references/notion-company-steward/workflow.md)。个人项目与日记格式保留在详细格式指南。

## 完整覆盖与完成标准

**默认要求：本次授权范围内的全部页面逐项验收，有缺口继续处理，最后列出实际未完成项；没有剩余也明确写“无”。用户无需重复提出。** 只读方案仍只读，指定章节仍限于该章；未验证项不得算作全部完成。

开始分析或优化前，必须读取[共同执行规则](references/completion-workflow.md)。默认检查用户指定的整篇或完整页面集合，建立覆盖清单，按内容质量补齐并持续执行到授权范围完成；分批写入不要求用户逐批说“继续”。只改某章、只整理格式或只要方案时遵守对应边界。

- **要求继承**：保留已确认架构、格式和排除项，新指令只覆盖对应事项；准确标题与位置不擅自改写或增加容器。
- **返工诊断**：继续完善前对照上轮目标与实际结果，区分遗漏、深度、结构、显示或新增需求，修复原因并检查同范围的同类问题。
- **双重验收**：分别核验结构组织与内容质量，任一适用必需项未通过就继续处理；视觉检查另行记录，不以标题或字数增加代替达标。
- “优化／执行”承接最近明确方案的交付对象；已授权的页面实施不退回另一轮建议，聊天提纲优化不自动变成 Notion 写入。
- 逐项记录已验证、无需改动、明确排除和受阻项；未读取不算已检查。事实与机制、例子与边界、资源保留及实际显示分别验收，不以新增标题或字数代替质量。
- 交付前核对全部承诺、章节清单与前后一致性；发现范围内缺陷继续修复，不把未完成事项包装成可选的下一步。真实工具障碍明确报告，并完成不受影响的工作。

## 维护入口

- **学科数据库的视图、卡片预览、页面打开方式与核心字段**：使用 [学科知识库管理规范](../notion-academic-database-manager/workflow.md)
- **工作流程、通用格式和权限边界**：修改本文件
- **学科、个人项目与日记模板和参考页面**：修改[详细格式指南](references/format-guide.md)
- **技能列表中的显示名称、简介和默认提示词**：修改 `agents/openai.yaml`

本文件及参考文档以中文说明规则；英文工具名、配置键、页面字段和双语示例保持原名。下文的笔记标点规则用于生成的 Notion 正文，不要求维护者在 Skill 说明里也使用同样标点。

## 执行流程

1. **确认工作区与知识树**：通过 Notion `fetch` 工具传入 `{"id":"self"}`，以返回的工作区 ID 和目标页面的祖先路径判断归属，不用显示名做唯一判据。当前 Felix 工作区 ID 为 `f1b034c8-c79e-4bf2-97cf-d2522b18fa05`，显示名为 `Felix.Y 的个人空间`；`Felix 的笔记本` 是旧称。若 ID 变化，先核对目标是否仍位于 `ACADEMIC 知识树` 及其实际页面结构，再决定是否套用规范；不能仅因工作区改名而停止已授权的页面维护。
2. **确认任务范围**：查看、分析和提出建议属于只读任务。只有用户要求相应操作时，才新建、修改、移动、重命名或统一页面。
3. **先读后改**：读取目标页面或数据库结构；有相近页面时，检查两到三个同级页面。通用模板应让位于当前页面附近的实际结构与习惯；用户明确指定的规则优先。
4. **识别页面类型**：区分知识树、公司研究、个人项目和日记。新建、重排或检查格式时，读取[详细格式指南](references/format-guide.md)；公司研究读取 [公司笔记管家](../../../industry-notes/references/notion-company-steward/workflow.md)。
5. **保留有效内容**：保留有意义的正文、关联、子页面、数据库、图片和属性。不能为了套模板而删除不符合模板的内容。
6. **控制修改范围**：只做实现目标所需的完整修改。未经明确授权，不批量统一历史页面、不纠正 `DAIRY` 等已有标签、不跨分支移动页面。
7. **复查结果**：修改后重新读取页面，核对标题、层级、属性、正文和子资源；流程图还需核对实际 Display 渲染与源码隐藏状态，Markdown 中存在图代码不等于显示模式已正确。说明已完成的修改及尚存的不一致。
8. **研究与引用**：新建或完善学科知识内容时，读取[教材与讲义参考规则](references/academic-sources.md)，优先依据适合当前层次的一流教材和官方课程讲义，核实实际相关内容后再编写；只整理格式不自动扩展为内容研究。除非用户明确要求，否则不向笔记正文添加 `References`、`Sources`、参考资料、书目或行内引用，核实依据在交付回复中简要说明。

## 从指令识别修改范围

根据当前指令和此前已接受的方案判断范围，不要求用户每次选择模式。仅在歧义会改变页面身份、章节结构或共享数据时澄清；范围清楚且已获授权时直接完成。

| 范围 | 典型指令 | 行为 |
|---|---|---|
| 方案分析 | 优化方案、展示一下、分析这个提议 | 只读；提供具体替换文字或调整后的完整相关提纲，说明改动理由，不只列原则，不写入页面 |
| 内容完善 | 补充定义、完善内容、优化这篇笔记 | 在既有章节下补齐必要的定义、条件、例子和反例；默认保留章节名称、顺序与页面归属 |
| 排版整理 | 整理格式、优化双栏、统一标题颜色 | 在授权范围内调整样式、列表与布局，保留内容含义和章节名称；不为凑模板扩写正文 |
| 结构重整 | 重整章节、可以大改架构、移动到某分支 | 仅实施明确授权的结构调整；单篇正文重整不自动授权修改数据库或同级页面 |

- 这些范围可以组合；“章节命名不要改，其他执行”表示保留章节名，执行此前方案中其余已授权项，不重复询问。
- “开始”“执行”承接最近明确且可识别的方案。用户排除的章节、属性或资源持续排除，不因后续简短指令重新纳入。
- 修正事实错误不受“保留内容含义”限制，但须说明实质性纠错；跨篇迁移和共享属性变更仍按授权范围处理。
- 只有用户要求教学时才切换讲解流程；整理笔记不自动展开测验、学习路线或封面生成。

## 通用格式

### 列表与表格的选择（轻度偏好）

- Felix 对学科笔记有一项强度不高的表达偏好：当清晰度相近时，优先采用原生有序列表，适当减少表格；这一倾向不构成禁用表格的硬性规则
- 概念、方法、步骤或比较对象通常可逐项展开，按当前层级组织有序条目；第五级继续使用原生小写罗马数字列表及已有的标签、换行规范，不为迎合偏好制造过深嵌套
- 当多对象多维度的横向对照、数据矩阵、对应关系等内容使用表格明显更清楚、更便于查阅时，仍使用表格；以内容结构、准确性和实际可读性为先，不要求为选用表格另行确认
- 该偏好不自动授权批量改动历史页面，也不要求机械拆解已有且清楚的表格；在本次已授权的新建或整理范围内按内容判断

### 章节架构与右侧辅助区

- 设计或优化章节时，采用简短、单一主题的标题，让每章职责清楚；将重叠内容归入最合适的章节，用关联连接相关知识，不反复讲解同一概念
- 学科正文的一级实质章节优先控制在 4–7 章，以 5–6 章为佳；未编号的 INTRODUCTION 不计入。该范围不要求每组 H2、H3 或 H4 也有同样数量；有分支数据库的学科父页继续遵循其专用正文顺序
- 章节英文名称优先控制在 1–4 个单词，以 2–3 个为佳；不计章节编号与中文译名。名称简短且准确，保留必要的通行术语，不为凑词数制造缩写或改变含义
- 二、三级标题优先描述本学科的对象、本质结构、内在分类、关系或作用机制，参考用户既有的命名风格，例如 `Group Basics 群基础`、`Group Types 群类型`、`Group Structures 群结构`、`Group Morphisms 群态射`、`Group Actions 群作用`。这些只示范按学科内容命名的方式，不是各学科必须套用的章节清单；属性解释与最小术语优先放在相关概念下展开
- 章节数量与深度由内容决定，不机械扩充；上述数量和词数是新建或获准重整时的优先范围。内容确需超出时优先保证知识归属、逻辑完整与准确命名，不为凑数合并无关主题、拆出空章或删减必要解释。简化架构时保留有效知识、例子与边界；只改局部不重排整篇，提出方案不等于获准改动页面
- 左侧承载完整理论、步骤、公式说明与适用边界；右侧只放对应的插图、短案例或例题，例子使用浅灰色 callout，不重复左侧正文，也不要求每节配图
- 右侧视觉素材优先考虑可靠的现成图片或适合的 ImageGen 插图，按知识点选择实物、界面对照、结构示意等；精确数值、几何或连接关系使用可核验的绘图工具，具体遵循 [学科插图](../academic-illustration/workflow.md)
- 不默认用 Mermaid Flowchart 填充右侧。只有操作顺序、决策分支、状态转换或反馈循环明显更适合流程图时才使用，简单线性关系可直接用短文字表达
- 使用 Mermaid 或其他流程图时，笔记只展示渲染后的图，不展示源码。写入前确认目标能直接渲染；不能确认时先渲染为图片再嵌入，不能把代码块作为最终交付。修改后检查实际显示，API 返回源码不等于已经显示成图

### 学习进度的维护边界

- `学习进度`由 Felix 自行判断并手动调整；AI 保留已有数值，不自动估算。仅在已授权的数据库维护任务中将空白初始化为 0%；只读任务不写入，单独的正文优化或格式整理不初始化空白，也不更新进度值
- 除数据库维护时将空白初始化为 0% 外，只有用户明确要求修改该属性时，才按用户指定的值修改；修改笔记正文不等于获准修改学习进度
- 打开页面时，`学习进度`在标题区以 Show as bar 进度条显示，并保留百分比数值；调整显示方式不得改动进度值，具体配置见[学科知识库管理规范](../notion-academic-database-manager/workflow.md#学习进度规则)

### 学科导论固定模板

学科笔记的导论开头固定使用以下结构与顺序，不因其他章节采用灵活架构而省略或改成其他层级：

```text
# INTRODUCTION 导论:
<columns>
	<column ratio="60">
		## A. Overview 概述:
		### a. Definition 定义:
		<ol type="i">
		<li>**Definition 定义:**<br>简称, 全称, 解释</li>
		<li>**Position 定位:**<br>按需要简述上级归属、相邻学科的边界及在知识体系中的作用</li>
		</ol>
	</column>
	<column ratio="40">
		[本学科当前封面图片块，使用已读取的封面资源]
	</column>
</columns>
```

- `INTRODUCTION 导论`是未编号的 H1，使用本笔记主题背景色并放在双栏外；`A. Overview 概述`是蓝色 H2，`a. Definition 定义`是橙色 H3
- **Overview 与封面固定并列**：以 `A. Overview` 为左栏起点，连同其下 Definition、Position 等内容放在左栏；本学科当前封面图片放在同一组双栏的右栏顶部，与 Overview 并列；如需 Connections 学科联系，在同一右栏的封面下方按需放一处，先封面、后学科联系，不作为必备块。读取当前目标学科的封面资源，保留原封面版本与页面封面属性；此处是正文内展示同一张图，不更换封面。H1 仍在双栏外，分支学科数据库仍紧接 H1 并位于该双栏之前。长度平衡不拆开 Overview 与封面这组并列关系
- 模板中的封面图片块是位置示意，实际写入时使用本学科已读取到的真实封面资源；示例的 60/40 仅表示新建默认值，不覆盖已有栏宽
- H3 下固定依次放 `i. Definition 定义:`、`ii. Position 定位:`；二者使用同组原生小写罗马数字有序列表，不新建 H5，也不额外插入 H4。标签加粗，说明在同一个列表块内换行
- 第一个 Definition 条目的正文固定按 `简称, 全称, 解释` 组织；没有通行简称时省略简称，写 `全称, 解释`。简称、全称与解释之间的分隔符固定为半角逗号加一个普通空格 `, `，不编造简称，不省略解释
- **Position 的内容职责**：用一小段自然文字，按需要说明本学科所属的上级领域、与容易混淆的相邻学科之间的区别和边界，以及在更大知识体系中承担的作用。详细的跨学科联系优先集中在导论右侧封面下方按需设置的一处 `Connections 学科联系` 折叠列表；其他章节仅在有独特理解价值时少量补充，避免重复展开。
- **Core Questions 的层级与职责（按需）**：需要概括本学科试图回答的主要问题时，在 `a. Definition` 下的同组原生罗马数字列表中，接在 Position 后追加 `iii. Core Questions 核心问题:`。它承担第五级标题作用，不创建 H5，不再默认设为独立 H2 章节；不要求每篇学科笔记都增加。条目使用 `<li>**Core Questions 核心问题:**<br>本学科试图回答的主要问题</li>`，与 Definition、Position 保持同一列表分组
- **起源或历史的适用范围（按需）**：仅在一级学科确有理解需要时考虑补充起源或历史信息，不列为所有学科的固定导论项。末端学科专题笔记不默认设置 Origin、History 或 Origin/Objectives 小节；已有有效内容继续保留，授权整理时再按知识归属处理
- 这里的 Definition 与 Position 是固定导论模板的必需项；其他知识条目的 Definition 仍按实际内容判断是否单列，不把这一固定模板扩展成每个概念的强制属性清单
- 含分支学科数据库的父页仍按下方专用顺序，将原生数据库放在 H1 之后、`A. Overview` 之前；没有该数据库的专题页不为套模板新建数据库
- 继续保留后续有效章节与内容。新建或在获准范围内整理导论时应用；本次更新 Skill 不自动改写历史 Notion 页面

### 学科父页的正文顺序

- 包含分支学科数据库的学科父页（如 `BUSINESS ADMINISTRATION 工商管理`），正文固定按 `INTRODUCTION → 分支学科数据库 → A、B、C 二级标题及内容` 排列。
- 第一行是未编号的 H1 `# INTRODUCTION 导论:`，沿用页面主题背景色；下一块紧接现有分支学科数据库，概述、定义或其他说明都放在数据库之后。
- 数据库之后放固定导论双栏：左栏从 `## A. Overview 概述:` 开始，包含 `### a. Definition 定义:` 及 Definition、Position 两个罗马数字列表项；右栏展示本学科当前封面。后续 `## B. ...`、`## C. ...` 等蓝色二级标题的名称和数量按实际内容确定。不要把这些标题、正文或双栏插在 INTRODUCTION 与数据库之间。
- 保留现有数据库的身份、父子关系、视图和数据；重排时原样保留其原生数据库块，不另建重复数据库。具体示例见[学科父页模板](references/format-guide.md#学科父页模板)。
- 这项顺序规则适用于学科父页，不要求没有分支数据库的专题正文页新建数据库，也不改变公司研究或行业 Wiki 的专用架构。

### 页面名称与双语顺序

- 页面和数据库标题采用 `ENGLISH 中文`，英文在前、中文在后；英文部分全部大写。
- 英文或中文有通行简称时，优先用简称；没有时使用全称。不要把简称的展开形式堆入标题。
- 在固定导论的 `INTRODUCTION → A. Overview → a. Definition → i. Definition` 条目中解释完整名称，按 `简称, 全称, 解释` 组织；没有通行简称时写 `全称, 解释`，分隔固定为半角逗号加一个空格。
- 示例：`DS 数据科学`、`NLP 自然语言处理`、`MLOPS 模型运维`、`DATA ANALYSIS 数据分析`；正文中可解释为 `DS, Data Science, 数据科学的定义说明`。
- 其他双语标签在与同级页面习惯相符时，也采用英文在前、中文在后。
- 优先保留页面既有术语，不悄悄替换成另一种译法。

### 标题层级、大小写与颜色

| 层级 | 编号与示例 | 英文大小写 | 颜色 |
|---|---|---|---|
| H1 一级标题 | `# I. TOPIC 主题:` | 全部大写，独立单词 AND 统一写为 & | 文本背景色，使用本笔记的主题色 |
| H2 二级标题 | `## A. Topic 主题:` | 标题式大小写（Title Case） | 蓝色文字 |
| H3 三级标题 | `### a. Topic 主题:` | 标题式大小写（Title Case） | 橙色文字 |
| H4 四级标题 | `#### I. Topic 主题:`（大写罗马数字 I、II、III） | 标题式大小写（Title Case） | 黄色文字 |
| 第五级（通过有序列表实现） | 原生罗马数字有序列表 `i、ii、iii`，不创建 H5 | 加粗双语标签，英文采用 Title Case | 沿用正文颜色 |

- **一级章节名的连接词替换**：学科正文 H1 的英文部分，独立单词 `and`（包括 `AND`、`And` 等大小写形式）统一替换为符号 `&`，符号与两侧词语各保留一个空格；其余英文继续采用全大写。例如 `# I. STRUCTURE AND FUNCTION 结构与功能:` 写为 `# I. STRUCTURE & FUNCTION 结构与功能:`。仅替换完整单词，不改动其他单词内部的字母；中文、章节编号及其他格式保持不变。此规则仅用于一级章节名，不扩展到页面或数据库名称、其他层级标题、正文、引用、代码或公式。新建或在获准范围内整理一级章节名时执行，本次更新 Skill 不自动批量修改历史 Notion 页面
- H2、H3、H4 使用标题式大小写（Title Case）：主要单词首字母大写；冠词、并列连词和介词（如 a、the、and、of、in、on）通常小写；标题首尾单词首字母大写。缩写、产品名和专有名词保留规范写法。
- 示例：`## A. US Domestic 美国国内`、`### a. Customer Segments 客户群体`。
- H2 蓝色文字、H3 橙色文字、H4 黄色文字是固定规则，除非用户明确对某个页面另作要求；这些是文字颜色，不是文本背景色。

### 学科简介不参与章节编号

- 学科笔记的 `INTRODUCTION 导论` 保持 H1 层级与本笔记主题背景色，但不加章号；第一个实质章节从 `I` 开始，后续连续编号。
- 示例：`# INTRODUCTION 导论:` → `# I. GROUP THEORY 群论:` → `# II. RING THEORY 环论:`。
- 新建学科笔记及授权整理标题编号时执行；只改某个段落时不借此重编号整篇历史笔记。用户明确说“INTRO 不算序号”时，调整该篇简介和后续章节编号，保留章节名。
- 公司、行业、项目和日记保留各自模板或用户指定规则，不把学科例外自动扩展到其他页面类型。

### 本笔记主题色的定义与选择顺序

- 一级标题使用文本背景色，颜色取本笔记的主题色，同一笔记的一级标题（包括简介）保持一致。
- **公司笔记**：主题色对应公司的品牌色。
- **学科笔记**：主题色对应这个学科的主题色。

- **优先级 2：相邻同主题笔记**。本笔记没有定义时，从相邻笔记中查找同一公司、同一学科或明确适用于本主题的既有主题色；不能只因位置相邻就套用无关主题的颜色。
- **仍无依据时**：公司笔记可依据可靠的官方品牌资料确定颜色；新建学科或在已授权的维护任务中需要确定空白主题色时，可参考本页已有主题背景色、学科常见对象、材料或现象的颜色，在[学科主题色规则](../notion-academic-database-manager/workflow.md#学科主题色规则)列出的九种颜色中先选一个，无需仅为初选配色再次确认，不新增或使用默认占位选项。这是可由 Felix 手动修正的初选，不声称是学科统一标准色；已有颜色及手动修正值继续沿用。其他类型沿用本笔记或相邻同主题笔记的既有定义。

### 第五级：原生罗马数字有序列表与正文标点

- 一至四级标题的 Markdown 标记依次为 `#`、`##`、`###`、`####`，井号后加一个空格；井号数量与标题编号是两回事。
- 四级标题编号使用大写罗马数字 `I`、`II`、`III`，二级仍用大写字母 `A`、`B`、`C`，三级仍用小写字母 `a`、`b`、`c`。
- 学科笔记的第五级通过原生罗马数字有序列表实现，编号为小写 `i、ii、iii`；这是知识层级的第五级，不创建 `#####` 或 H5 标题块。保留已有罗马数字列表及其分组、顺序与嵌套。
- 通过 Notion MCP 写入前读取当前正文格式规范；支持 `<ol type="i">` 时，使用该容器包住同组 `<li>...</li>` 条目。不要用普通 Markdown 的 `1.` 或手写 `i.` 段落代替原生罗马数字列表；若实际工具无法设置该样式，说明限制并将编号样式列为未完成，不把替代格式报告为达标。
- 写入 Notion 时核实当前工具对四级标题及列表编号样式的支持；无法原样呈现四级标题时说明限制，不把降级格式报告为原生 H4。
- 每个新增编号条目先写**加粗的双语标签＋冒号**，再在同一列表块内换行写解释。
- 每组使用一个 `<ol type="i">`，每项使用一个 `<li>`；标签与说明必须处于同一个编号列表块。说明用软换行连接，含公式时仍遵循下方三行规则。写入后回读核对罗马数字编号样式、条目数量、内容与嵌套；结构回读与界面显示检查分开报告。
- 新写的笔记正文用半角逗号 `,`，不用中文逗号 `，`；逗号后还有下一短语时加一个普通空格。
- 普通段落和解释性列表项的末尾不加 `。` 或 `.`。
- 代码、URL、引文、缩写、数据值和其他需要原样保留的内容，其必要标点不得删除。

### 第五级的知识单元与解释角度

第五级在知识层级上承担最小知识单元的标题作用，实际使用原生小写罗马数字有序列表 `i、ii、iii`，不是 Notion 的 H5 标题块。沿用加粗双语标签、冒号与同一个列表块内的软换行。

- **H4 分组的考虑时机**：同一 H3 概念下尚未用 H4 分组的第五级条目超过 6 个，即达到 7 个及以上时，开始考虑按内容关系组织 H4 分组；统计该概念的第五级知识或属性条目，不把右侧案例内的细节编号或其他 H3 的条目累加。超过 6 个是开始评估的提示，不自动触发拆分；只有内容确实形成有意义的知识组且本次获准调整结构时才实施。6 个及以内不单因数量新增分组。保留已有已确认的 H4 结构及用户布局，不因某组不足 7 个而删除或合并；分组后各组也没有固定的条目数量配额
- **解释上级概念的属性**：在相关 H3 或 H4 概念下，按理解需要选择下表角度；不要求每个概念全部列齐，不为属性多建一层空标题
- **独立术语知识点**：第五级本身也可以是一个最小术语或概念。第一行写加粗双语术语与冒号，换行后先解释规范全称与含义；已有缩写时展开其真实全称，无缩写时直接解释该术语，不编造全称或别名。随后按需要补充机制、条件、用途或短例子，不强制再嵌套一整套属性列表
- **解释顺序**：完整概念的属性通常先写 Definition；已有定义而本次只补动机、应用等局部内容时，不重复追加定义。数学完整概念条目也按实际内容判断是否单列 Definition，并遵循下方适用的形式化定义要求。学科导论的固定 Definition、Position 开头按[固定模板](#学科导论固定模板)执行

| 解释角度 | 使用条件与作用 |
|---|---|
| Definition 定义 | 绝大多数概念适用，通常优先，说清对象是什么、所属类型及区别条件；是否单列按实际内容判断 |
| Formal Definition 形式化定义 | 通常用于数学学科；有适用的严格定义时写对象、符号和必要条件，非数学笔记不为套模板强加形式化表达 |
| Formula 公式 | 表达关系、计算或规律，说明符号、前提与适用范围；不把任意公式当作概念定义 |
| Applications 应用 | 说明知识如何被用于解决问题 |
| Situations 场景 | 说明知识出现或适用的具体情境，与应用有实质区别时分别保留 |
| Motivation 动机 | 说明为什么引入概念或方法、它解决什么困难 |
| Properties 性质 | 说明对象的重要特征与结论，保留必要条件 |
| Intuition 直觉 | 用熟悉对象或图景帮助理解，保留类比的边界 |
| Core Idea 核心思想 | 解释构造或机制中最关键的一步 |
| Examples 例子 | 左侧作为概念属性，以具体对象、现实现象等词语列举帮助理解抽象概念；右侧用完整案例讲解左侧概念，职责见下方 Examples 左右分工 |

选择对当前知识真正有帮助的角度，合并重复解释；定理、判定、反例等原有角度仍可按需要使用。形式化定义通常属于数学说明，不能仅因概念看起来抽象就编造公式。含公式条目仍按下面的名称、公式、解释三行顺序书写。

### Examples 的左右分工

- **左侧 Examples 是概念的属性角度**：选择这个角度时，在相关概念下用一个第五级原生罗马数字 `Examples 例子:` 条目，列举能帮助理解抽象概念的具体对象、现实生活现象、典型情境或数学对象的名称。它用具体词语建立直观联系，不承担完整案例讲解
- **词语式内容**：每项用一个词语、名称或简短短语，可以是中文，也可以是 `English 中文`。需要多少项由概念决定，不固定只列几个；各项之间统一用半角逗号加一个空格 `, ` 分隔，双语名称内部英文与中文之间用一个空格。整份清单留在同一个 Examples 编号条目内，不把每个词语另列为一个罗马数字条目，也不扩成逐项解释的段落
- 格式示意为 `English 中文, English 中文, 中文词语`；数学符号仍按“符号＋空格＋名称”的既有规则书写，不列裸符号
- **右侧例子是完整讲解**：围绕左侧概念选择具体对象或情景，按需要交代背景、成立条件、与概念的对应关系、机制、计算或验证过程和结论，帮助读者真正理解左侧概念。右侧保留完整案例，不只重复左侧词语；完整文字或计算例子使用浅灰色 callout，图表沿用已有规则
- 左右分工按内容职责判断，不以文字长短互换：左侧继续是简短列举的概念属性，右侧承担完整讲解。是否添加 Examples 和需要多少右侧例子按知识需要判断；保留已有有效内容和用户已调整的布局，不为凑词语数量或对齐扩写

### 公式条目的三行排版

**重要公式放在第五级原生小写罗马数字有序列表条目中，不创建 H5。学科笔记新增或在授权范围内整理的公式条目，采用同一个列表块内“标题行 → 正文第一行公式 → 正文第二行起解释”的固定顺序。标题行不计入正文行数；这与下方按整个条目计数的三行顺序一致：**

1. **第一行是名称**：加粗双语名称＋冒号
2. **条目第二行，即正文第一行，只放公式**：使用 inline equation 行内公式 `$\boxed{...}$`，以一个 `\boxed{}` 框住一个核心形式化表达。该行只显示这一个公式框，不并排放多个框、不嵌套方框；公式名称、中文说明、英文解释句、符号释义及推导段落都不放进框内或挤在这一行
3. **条目第三行，即正文第二行，开始解释**：以中文说明公式含义、符号与变量、成立条件、适用范围及内容逻辑，需要时展开必要推导；这些说明全部从这一行起安排，不抢占前面的公式行。定义本身不可缺少的量词和形式化约束仍保留在核心公式中，避免因精简破坏公式含义

写入时在同一个 `<li>` 列表块内用 `<br>` 或编辑器软换行连接这三部分，公式使用原生 inline equation，不把公式和解释拆成新的编号项或独立块公式 `$$...$$`、`\[...\]`，也不把公式源码作为代码文本展示。左右两栏的公式条目与例题计算均采用此顺序；没有公式的文字条目仍使用“名称 → 换行解释”，不为套格式编造公式。解释中的辅助记号保持行内显示，不必逐个加框

长公式优先拆为各自完整的条目；确需保留为一个整体时，可在同一个行内公式、同一个 `\boxed{}` 内使用 `aligned`，框内仍只放必要的形式化表达，不混入说明文字。标题、公式与解释的顺序保持不变。检查实际渲染、软换行、边框数量和栏宽，右侧 callout 内的公式也须留在其内容区内

```text
<ol type="i">
<li>
<b>Conditional Probability 条件概率:</b><br />$\boxed{P(A\mid B)=\frac{P(A\cap B)}{P(B)}}$<br />要求 $P(B)>0$, 先把样本范围限制到 $B$, 再用 $P(B)$ 归一化
</li>
</ol>
```

这是今后的默认格式, 不自动授权批量修改历史页面；本次用户明确指定其他格式时按当次要求处理

### 数学概念的解释规范

用于数学笔记中新概念的编写与授权范围内的内容完善, 群论只是示例, 同样适用于其他数学分支。概念标题沿用所在位置的层级与编号, 不为套用示例新增章节；只更新 Skill 不自动修改历史 Notion 页面。

**完整概念条目默认优先考虑 Definition，绝大多数情形适用，但不作为一律必备项；是否单列以及放在何处，按具体内容和理解需要判断。Formal Definition 有适用的形式化定义时就近安排，通常接在文字定义之后。** “约九成”表达默认倾向，不是数量配额或验收比例；已有清楚解释、当前内容不适合独立下定义，或本次仅补某个角度时，不为套标签重复或编造定义。 用户只要求补充已有概念的某个角度（如只解释动机或一个例子）时, 只补该部分, 不重复或重写已有定义。后续按理解需要选择角度, 不要求每个概念凑齐所有条目。每项采用加粗双语标签与同一列表块内的换行解释, 编号样式遵循第五层规则。

1. **Definition 定义（默认优先，按需）**：适用并单列本项时，正文采用 `English 中文, 又称 English 中文, English 中文, 文字定义`。有一个别名时只保留一个, 无别名时写 `English 中文, 文字定义`；多个真实通行别名在一个“又称”之后依次列出, 每个都保持英文在前、中文在后。定义用简明文字交代对象是什么、所属类型及区别条件, 不只给译名或比喻。别名须在当前语境确实同义, 不把相关概念或更宽泛的类别列为别名。
2. **Formal Definition 形式化定义（适用时必须）**：默认只写一个最核心的行内 `$\boxed{...}$` 公式, 按上述三行规范放在有序列表第二行, 第三行起解释符号与必要前提；已有明确上下文不重复展开。复杂定义确需多行时使用 `aligned` 等换行, 不把同一条件的展开、等价判定、群公理验证、推导与例子全塞入本项, 分别放到对应位置。公式必须定义当前概念, 不为简短将上位概念、特例或相关概念的公式冒充其定义。没有适用形式化定义的动机、直觉或方法说明不编造公式。公式保留规范 LaTeX 转义, 避免复制网页中的多余反斜杠、HTML 实体或损坏的加粗标记。

| 可选角度 | 回答的问题与内容要求 |
|---|---|
| Formula 公式 | 相关的计算关系或规律是什么, 说明条件与符号, 与形式化定义分开 |
| Applications 应用 | 这个概念或方法如何用于解决问题 |
| Situations 场景 | 在什么具体情境中会遇到或适用, 避免与应用重复 |
| Motivation 动机 | 为什么引入这个概念, 原有工具遇到什么困难 |
| Core Question 核心问题 | 这个概念要解决或刻画的一个明确问题 |
| Intuition 直觉 | 用熟悉的对象或图景解释含义, 保留适用边界 |
| Core Idea 核心思想 | 抽出构造或机制中最关键的一步, 不重复文字定义 |
| Properties 性质 | 从定义得到哪些重要结论, 写清条件与适用范围；多条性质按下方标题与列表规则组织 |
| Examples 例子 | 左侧用词语、名称或简短表达列举具体对象，帮助理解抽象概念；数量按需要，各项用逗号加空格分隔；右侧浅灰色 callout 提供围绕左侧概念的完整讲解与条件验证 |
| Theorems 定理 | 写清假设、结论与用途, 深度需要时给简短证明或证明思路 |
| Criterion 判定 / Equivalent Conditions 等价条件 | 给出验证概念的条件或等价刻画, 与原始定义分开标注 |

- **选择与去重**：优先补足当前理解缺口，按概念实际需要选择解释角度，不设默认数量范围；合并重复内容，不为凑数量增加条目，也不为限制数量压缩必要解释。Motivation 与 Core Question, Intuition 与 Core Idea 若表达同一件事, 合并或选其一；多个角度有不同职责时可同时保留。简单概念允许只写必要定义与一个短解释, 复杂概念按内容展开。
- **区分逻辑角色**：Definition 说“是什么”, Formal Definition 写精确条件, Properties / Theorems 写由条件推出的结论, Criterion 写如何判定。等价刻画单独标明；例如 `\ker\phi=\{e_G\}` 是群同态单射性的核判定, 使用时必须有“\(\phi:G\to H\) 是群同态”的前提, 不用于任意映射。
- **数学准确性**：首次出现的记号可辨认, 量词、对象类型与前提齐全, 区分“定义为”“推出”与“当且仅当”；直觉不代替定义, 例子需实际满足条件, 有实质风险的常见误解就近说明。只保留服务于当前概念的性质与定理, 不展开无关整章。
- **四级分组的统一结构**：先按上方“第五级条目超过 6 个时开始考虑”的标准与内容关系评估分组；不把它当作每个 H3 都必须拥有 H4 的要求。决定将多条性质组织为独立 H4 时, 前面的概念介绍也必须有同级 H4, 在相关概念下保持两组同级，通常为 `#### I. Definition 定义:` 与 `#### II. Properties 性质:`；确无适用定义内容时，第一组按实际概念介绍内容命名，不创建空 Definition 分组。第一组保留适用的 Definition、Formal Definition、动机、核心思想和简短 Examples 等有序项；第二组每条性质一个真正的有序列表项, 每项以加粗双语性质名称与冒号开头。其他实质分组确有需要时继续同级编号, 不留下“前面无分组标题, 后面单独 Properties”的混合结构。不把全部性质压在一个编号项里, 不为每条性质创建更深标题；概念已有 H4 时按明确授权调整相关局部层级或就近关联分组, 不创建 H5 或擅自重排其他章节。没有独立性质分组时不机械添加空的四级标题。
- **左侧例子的符号与名称**：Examples 使用数学符号时, 每个符号后加一个普通空格和对应名称, 如 `$GL_n(F)$ 一般线性群`, `$SL_n(F)$ 特殊线性群`, `$O(n)$ 正交群`；不只列一串裸符号, 不把 GL 误称为“一般矩阵群”。名称可按当前语境使用简短中文或双语，保持词语式列举，帮助将抽象概念联系到具体对象；各项用半角逗号加一个空格分隔，完整讲解与验证放右侧。
- **正文与说明区**：定义、形式化条件、动机、核心问题、核心思想、性质与定理放左侧知识主线。左侧 `Examples 例子` 是概念的一个属性条目，以词语、具体对象或现实现象的名称及简短数学表达作列举，帮助理解抽象概念；各项用半角逗号加一个空格分隔，数量按概念需要决定；详细对象、计算过程、条件验证与反例适合展开时放对应右侧, 完整文字或计算例子使用浅灰色 callout 包住, Markdown 指令示例为 `<callout color="gray_bg">...</callout>`。实际写入创建原生 callout 并设置 `gray_bg`, 不用普通引用块冒充浅灰色 callout；宽表格与独立插图仍可直接放右侧。短直觉与易错提醒也可放右侧；没有实质右侧内容时保持单栏, 不为凑齐角度或对齐扩写。具体示例见[数学概念示例](references/format-guide.md#数学概念示例)。
- **交付前检查**：逐概念判断 Definition 是否适用、已有解释是否充分，以及采用的 Formal Definition 是否精简准确；不把缺少 Definition 标签本身判为不合格, 核对重要公式位于第五级原生罗马数字条目，同一列表块内标题后换行，正文第一行只有一个干净的框选行内公式，正文第二行起解释；检查框内没有名称、说明或符号释义， 检查别名真实性、必要前提与符号、定义和结论的区分、Definition / Properties 四级分组是否统一、左侧例子是否简短且符号带名称、右侧完整例子的 callout 与有效性及角度是否重复；用户指定局部范围时仅检查该范围。

### 学科笔记的正文与说明区

- 左侧正文区承载学科知识主线，例如概念、定义、公式、推导、性质和方法；右侧说明区可放例子、例题、计算、图示、用于讲解程序本身的代码和学习问题；流程图源码不属于阅读区代码示例。
- **学科联系低频放在右侧折叠列表**：`Connections 学科联系` 是补充说明，使用原生 Toggle List；优先在 INTRODUCTION 导论右栏的封面图下方按需出现一处，顺序为封面图、学科联系，不要求每篇都补建。其他章节仅在某个联系对理解当前知识点有独特帮助、且未被导论或已有条目覆盖时少量添加；不按章节或概念固定重复，不把“平均每章一次”当作目标或配额。折叠标签采用加粗双语名称，不作为左侧正文或双栏外的编号章节，也不用 Toggle Heading 代替。展开后保留学科关联说明与原生页面引用；具体结构见[格式指南](references/format-guide.md#学科联系折叠列表)。已有内容在本次授权范围内按实际价值整理去重，不因技能更新批量删除或迁移历史页面。
- **插图不标来源，说明只按需补一行**：笔记中的插图不添加来源、图源或 Source 标签，不附来源段落。图片单看已能理解时不加外部解释；只有单看无法理解图在讲什么或与当前概念的关系时，才补一行简短说明。图内已有讲解时不再添加外部说明，不重复图内标题、结论或正文讲解；图片内容与对应知识点的准确性仍需核对。
- **一级标题始终在双栏外**：包括 `INTRODUCTION` 在内的全部 H1 独立占据整行，不放入任何左栏或右栏。章节编号、名称、顺序与主题背景色保持不变。
- **正文双栏默认从 H3 并列起头**：新建正文双栏时，默认以一个 H3 三级标题为分组起点，将 H3 本身放在左栏顶部，其下 H4、第五级条目和所属正文一起保留在同一左栏；右侧对应的插图、例子、例题或代码从该组双栏顶部与 H3 并列开始，而不是等到 H4 或某个正文段落后才起头。H2 通常在该组双栏之前承接上层组织；导论固定从 H2 `A. Overview` 与右侧封面并列，仍按专用模板处理。该规则是新建双栏的默认方式，不要求每个 H3 都新建双栏；没有实质右侧内容时可保持单栏。保留用户已调整的现有分组、起始位置和比例；确有内容需要或用户另有指定时，在授权范围内采用其他起止边界。第五层仍是原生有序列表，不创建 H5；右侧例子使用加粗双语标签，不占用正文的章节编号。
- **新建双栏的比例与已有比例保留**：只在新建双栏时默认左 60% / 右 40%，可按文字与图片的实际需要选择 5:5、6:4 或 7:3。已有双栏沿用当前比例，保留用户手动调整；尤其不把非 5:5 的比例当作错误，也不为套用默认值或对齐而改成 5:5 或 6:4。只有用户明确要求调整已有比例时才修改。导论以 Overview 左、当前学科封面右固定并列；其他正文右侧没有实质辅助内容时可保持单栏。图、表、公式与 callout 的高度均计入两侧布局判断。
- **知识完整与图文对应优先**：优先保持完整的知识单元，让辅助内容靠近对应正文；不要求逐段、逐条严格对齐。同一一级章节内邻近主题的例子或插图可在不影响对应关系时适度错位，保留明确标签以避免误配；不为平衡长度而打乱知识归属或用户已调整的布局，不把不相关内容或另一章的辅助内容搬来凑齐。
- **约 5 行只作视觉参考**：按当前栏宽下实际显示的文本行高估算，两侧底部相差约 5 行仅供视觉判断，超过也不自动触发重排、拆栏或合栏。保留用户已调整的布局，包括既有分组、比例和图文位置；只有明显影响阅读且本次授权允许调整排版时，才在完整段落、例子或小节边界处理，优先保持知识单元完整及图文对应。比例调整仍按上方保留已有比例的规则处理。5 行不是源 Markdown 行数或硬性等高要求，不为消除差距拆碎内容或插入空白；无法查看实际渲染时说明仅按内容长度估算。
- **部分例子可用浅灰色 callout**：短例子、手算与易错提醒可使用 `gray_bg`；较宽的表格和插图直接放在右栏，不要求所有辅助内容都包入 callout。不为对齐删减有效知识、扩写无关文字、压缩字号或添加占位资源。
- **默认不添加学习路线类内容**，包括学习顺序、学习路径、学习建议、复习路线或类似的导航性小节。不要为了凑齐章节而新建这类内容。
- 只有学习路线确实能帮助理解当前知识结构，且页面有合适的右侧说明区时，才将其作为简短辅助说明放在右侧；不要将它设为左侧正文区的章节、学习主线或必备模板项。
- 没有合适的右侧说明区时，省略学习路线，不为它单独创建空白双栏。已有页面中的相关内容先按任务范围和保留有效内容原则处理，不因本规则自动批量删除或迁移。

### 流程图显示：只展示 Display

- **所有流程图只展示渲染图**：学科笔记正文、右侧说明区、callout、折叠区及交付预览中的 flowchart 默认只显示 `Display` 图，不显示 `Code` 源码，也不使用图与代码并排的模式。Mermaid 的 `flowchart` / `graph`、状态图、时序图等图示均采用这一展示规则。
- **源码用于制作，不作为交付内容**：允许内部使用 Mermaid 或其他图形源码生成图；写入原生 Mermaid 块时选择 `Display`，不额外复制源码到正文、callout、折叠区、代码附件或回复中。展示规则不影响 HDL、Python 等用于解释程序本身的代码示例；用户明确要求查看或编辑图源码时按该次要求处理。
- **按真实能力设置模式**：先核实当前工具是否支持图块显示模式；支持时设置为 `Display`。接口仅支持 Markdown 或源码写入时，不编造显示属性，不把 `mermaid` 语言标记当作已隐藏源码；可用编辑器 UI 时切换到 `Display` 并核对实际图形。界面可能将同一模式标为 `Preview` 或 “Show only preview and hide code”；以实际仅显示图形、隐藏源码的行为为准。
- **无法设置模式时使用渲染图**：优先交付或嵌入已渲染的图像，确认节点、箭头、标签与原图一致且清晰；不要为了隐藏源码直接删除图或用空白占位。保留已有资源和必要的可编辑来源，不在阅读区重复展示源码；无法渲染或验证时准确说明尚未完成的显示检查。
- **检查所有可能露出源码的位置**：本次授权页面中的正文、双栏、callout、折叠区和嵌套块，以及方案预览、最终回复和附件均需检查；避免同一图以渲染图与原始代码重复出现。整页替换、复制图块或重新写入 Mermaid 后必须再次检查显示模式，不能假定原先的 Display 设置会被继承；切换后重新读取实际界面，确认图形仍在且源码不可见。此次技能更新不自动授权批量修改历史笔记。

## 修改权限与异常情况

- 读取权限不等于编辑授权；修改一篇页面，不等于可以修改它的数据库、同级页面或上级页面。
- 广泛迁移、属性结构变更、页面移动、删除和批量重命名需要用户明确授权；已有明确授权时不重复询问。
- 找不到相近同级页面时，采用格式指南中的标准结构，并向用户说明不确定的设计选择。
- Notion 连接不可用时，可提供草稿，但必须说明尚未写入或验证。

# 学科插图

插图服务于理解具体知识点。先判断读者需要看清什么，再决定是否需要图片、图片承担多少讲解，以及使用什么来源。不要默认把每个概念都做成同一种海报或完整教学图。

## 在笔记中的位置

- 学科笔记采用双列排版：左侧是概念、知识点和正文；右侧是与左侧对应的插图、例子、例题或代码
- 将插图放在对应知识点的右侧，就近配合左侧讲解；一张图服务一段具体内容，不集中堆在章节末尾
- 先读取最新页面，识别对应段落及既有列结构。沿用现有列宽、位置和内容，保留用户刚做的排版调整
- 目标段落只有单列且已授权添加插图时，只将相关局部整理成双列；不为插图重排整篇笔记
- 按右侧列的实际展示宽度设计并检查可读性。信息太密时删减或拆成连续小图，不依赖放大后才能阅读
- 不套用封面的固定 16:9 比例、电影感或大幅标题；比例由实物形态、概念关系和列宽决定

## 右侧辅助区的图片与流程图

- 优先考虑可靠的网络现成素材或适合的 ImageGen 插图，用实物、界面对照、结构示意或具体情境帮助理解；质量取决于内容正确、用途匹配和实际列宽下可读，不凭制作方式或视觉精致判定
- 不将 Mermaid Flowchart 作为右侧默认素材，不为每节重复制作方块箭头图。短案例或现有图片足以解释时不新增图
- 只有顺序、分支、状态转换或反馈循环是核心理解对象，且流程图明显更清晰时才使用流程图；精确关系仍使用可控绘图工具，不能为了图片优先让 ImageGen 猜测连接或数值
- 流程图只交付和展示渲染结果，不在笔记中展示 Mermaid 源码。确认目标原生渲染可用后才使用；无法确认时先渲染成图片并嵌入，不能将源码代码块当作成品
- 写入后检查目标页面实际显示、标签可读性及右侧列宽；只读 API 中存在 Mermaid 代码不证明图已渲染，未做视觉检查时如实说明

## 判断图片承担的任务

从左侧正文找出一个具体的视觉问题，例如“设备长什么样”“这个部件在哪里”“两种情况有什么区别”“这个过程如何发生”。选足以解决问题的表达方式，可以组合使用，但不强求图中包含全部定义和推导。

| 任务 | 适合的表达 | 内容边界 |
|---|---|---|
| 实物识别 | 设备、仪器、标本、建筑或作品的真实照片 | 展示实际外观即可，必要时标出一两个重要部位 |
| 局部识别 | 实物或可信结构图上的少量箭头、圈选、标签 | 只标出正文正在解释的部分，不制作全套零件清单 |
| 辅助理解 | 简洁的几何示意、结构剖面、对照图、路径图 | 让一个难以想象的关系变得可见，主要讲解仍在左侧 |
| 完整概念讲解 | 分步过程、具体例子的状态变化、因果或运算图解 | 图中包含必要条件、关系与结果，但不复制整段正文 |

如果文字、一个例题或现有图片已足以说明问题，不为装饰而新增插图。完整概念图也不是每个知识点的默认选择。

## 构图前的判断

先用一句话明确“读者看完后，应能指出、区分或解释什么”。再确定以下三件事，不必把这份设计判断写进笔记或图片：

- **对应正文**：图片服务哪一段，哪些解释已经在左侧，因此不需要重复
- **视觉证据**：必须让读者看到的对象、差异或变化是什么；只把文字装进框里不算完成视觉化
- **正确性约束**：哪些连接、方向、顺序、尺度、数值或部位绝不能画错

根据视觉问题选构图，而非按学科套模板：认识对象用实物；定位部位用局部高亮或剖面；比较差异用相同视角的并置；理解过程用连续状态；理解层级用嵌套或分层；理解对应关系用清晰映射。不要把时间、空间、因果和包含关系都画成无区别的箭头。

## 主体与阅读路径

- **主体优先**：设备、结构、几何关系或状态变化占据主要画面。标签靠近目标，少用大标题、卡片框和图例挤占空间
- **总览与局部配合**：总览图负责建立位置关系，局部图负责解释机制。完整讲解指把当前问题讲完整，不等于一张图塞入整个章节
- **连续追踪**：过程图保持同一对象、颜色、视角和比例约定；让读者能追踪一个数据、粒子、部件或变量，突出每一步真正变化的部分
- **比较控制变量**：对照图保持布局、尺度和视角可比，只突出需要理解的差异。非比例图明确标示，不让尺寸暗示未经核实的数量关系
- **形式可以变化**：真实照片、写实剖面、立体示意、平面关系图均可使用；统一术语和颜色含义，不要求统一卡片模板
- **控制讲解深度**：正文插图允许只做辅助；独立概念图应补齐理解当前问题必需的条件。不要机械禁止所有解释文字，也不要为了“完整”复制正文

## 选择来源与制作方式

- **真实对象和观察证据**：优先从官方厂商、大学、博物馆、研究机构、开放教材或原始论文寻找照片、显微图、实验图及结构资料。核对对象、型号、尺度和语境，不能用生成图代替真实观察
- **现成教学图**：先判断可靠图源是否已清楚表达当前知识点；有合适图就直接选用，不必重新生成。必要时只裁出相关部分或添加少量标注
- **ImageGen**：适合原创情境、直观类比、定制示意、部件高亮及需要视觉组织的概念讲解。给出明确的教学目标、对象、关系、关键方向和必须保留的条件，不只要求“画得漂亮”
- **精确图形**：坐标、函数、数据、数学运算、精确拓扑、电路等优先使用可核验的绘图或专业工具。真实数据图保持数据含义；不要让生成工具猜数值、曲线和连接关系
- 只有方块、箭头、标签的关系图，以及要求等长、等面积、准确对齐或严格连接的图，默认直接采用可控绘图工具。ImageGen 适合对象与情境的视觉表达，不承担精确几何排版；用户指定 ImageGen 时可试作，但如实报告未满足的约束
- **混合制作**：可用可信实物图加局部标注，或用生成的场景配合精确绘制的箭头、公式和图表。来源选择服从解释任务，不要求统一由 ImageGen 制作
- 使用 ImageGen 生成或编辑图片时遵循当前可用的 imagegen Skill 与工具；不要为了批量一致性把所有学科都强制转换成同一视觉模板

## 设计概念图

- 从一个具体对象、问题或小例子入手，展示变化、比较或关系，再连接到抽象概念
- 每张图优先解决一个核心理解障碍；多步讲解让读者看得出起点、关键变化和结果
- 用空间位置、箭头、颜色和局部放大表达信息。箭头应有清楚含义，颜色应帮助追踪同一对象或区分类别
- 只保留理解所需的文字。简图可以没有标题；需要标题时保持短小，双语也应控制密度
- 左侧已有的定义、完整推导和管理说明不搬进图中；图内公式只保留帮助看懂图的部分
- 示意、类比、模拟数据或非比例绘制会影响理解时，在图内简短注明；不要把类比画成事实结构
- 不添加跨笔记序号、Figure 编号或“01–06”系列标签。表示运算值、坐标或步骤顺序的数字可以保留
- 图片里已有标题或结论时，图外不再添加重复的“某某图解”、`Key Insight 看图结论`、概念复述或说明段落
- 不默认加入统一品牌条、栏目标签、水印、装饰背景或概念图谱大标题

## 实际工作流程

**分析或建议请求**：读取相关笔记，指出具体段落的理解障碍、适合的图类型、来源或制作方式。区分辅助图与完整讲解图，不擅自生成整批图片或写入页面。

**选图或制作请求**：读取相邻正文，确定图需要回答的问题与右侧展示条件，选择最合适的方法后制作。用户未确定的批量风格可先做有代表性的样例供其判断；已经确定的任务按授权继续，不反复要求确认。

**写入请求**：在最新页面中做局部修改，把图片放在对应右侧列。修改后重新读取，核对原有正文、媒体和列结构，并在实际列宽下检查图片显示。接口失败后按问题选择一次有依据的替代方式；不能匹配目标时停止该处写入并说明，不用全页替换来绕过定位问题。

**质量检查**：图片是否解决明确问题；实物和标注是否正确；关系、方向、数值和条件是否成立；右侧宽度下能否读懂；是否与左侧重复；是否保留原有内容。生成图尤其检查文字、箭头和科学结构，不凭视觉精致就判定通过。

在生成前把必要标签、映射或步骤固定下来，生成后逐项核对。缩到目标列宽检查；暂不知道页面列宽时，可按约 400–600 像素宽预览判断，不把该范围当成固定排版规则。若文字或路径无法辨认，应减少内容、增大标注或拆图，不单纯提高分辨率。结构、映射或方向出错的图片先修正再作为成品交付；修正失败时明确说明限制。

同一处精确约束连续两次定向修正仍不满足时，停止重复生成；改用适当工具重新制作，或明确标为尚未通过的样例。不能把提示词中的要求当成生成结果已经满足的事实。

用户要看样例时，优先选择不同教学用途的少量例子，例如一张对象结构图与一张机制图，以便判断表达方式。样例直接在对话中展示，只有用户要求应用时才写入笔记；不要将样例阶段变成批量出图。需要额外费用的生成或素材服务不自动启用。

**交付与清理**：只简短报告实际完成的修改和页面链接。不保留本地插图存档、预览合集、页面备份或过程文件；确需临时文件时，在图片已可靠交付并验证后清理本次生成的文件。Skill 本身及其必要资源是维护原件，应保留。

# 学科知识库管理规范

本文件是可直接编辑的 Markdown 规范原件。维护 Felix 工作流中学科数据库的视图、属性和页面布局；用户在当前任务中的新要求优先于本文。修改本文件只更新工作流，不等于已经修改 Notion。

## 适用范围

- 适用于 `ACADEMIC 学科` 知识树中的学科地图、学科分支库与学科专题库
- 行业、公司、软件产品、品牌和工具目录不自动套用此规范
- 修改知识正文、标题颜色、公式或章节时，另读 [学科笔记规范](../notion-note-steward/workflow.md)，沿用目标页面的内容与格式

## 三视图与固定顺序

视图从左到右固定为：**学科概览 → 分支概览 → 学科信息**。这是当前规则，替代以前 Gallery → Table → Board 的排列。

| 顺序 | 视图名称 | 视图类型 | Open pages in 打开方式 | Card size 卡片大小 | Card preview 卡片预览 | 属性显示 |
|---|---|---|---|---|---|---|
| 1 | 学科概览 | Gallery View 画廊 | Full Page 全页 | Large 大 | Page Cover 页面封面 | 卡片隐藏全部属性 |
|  |
|  2| 学科信息 | Table View 表格 | Side Peek 侧边打开（Side Page） | 不适用 | 不适用 | 学科名称、分支、学科难度、学科层级、学习进度、学科主题色 |

### 学科概览

- 卡片展示页面封面、主题图标和学科名称；不展示分支、学科难度、学科层级或其他 Property 属性值
- Card size 必须为 Large，Card preview 必须为 Page Cover， 点击卡片以 Full Page 打开笔记
- 隐藏卡片属性不会删除数据库属性，也不要求将打开后的笔记页面全部属性隐藏

### 学科信息

- 用于集中查看与编辑属性，列顺序为 `学科名称 → 学科分支 → 学科难度 → 学科层级 → 学习进度 → 学科主题色`；有独立用途且原来可见的其他字段接在其后
- 保留有效的已有筛选和排序；标题属性改名后，同步检查按名称排序的引用
- 表格点击条目以 Side Peek 侧边打开，便于在查看笔记时继续编辑和对比表格

## 标题、图标与核心字段

页面和数据库标题采用 `ENGLISH 中文`，英文在前并全部大写；主题 emoji 作为独立图标，不重复写进标题。沿用既有封面，只有用户要求更换时才修改封面。

标题属性之外，统一三个学科分类字段：`分支`、`学科难度`、`学科层级`，一个由用户手动维护的进度字段：`学习进度`，一个真实成绩字段：`学科成绩`，以及一个供 AI 读取的隐藏字段：`学科主题色`。

| 字段 | 类型与含义 | 维护规则 |
|---|---|---|
| 学科名称 | Title 标题属性 | 统一属性名；改属性名不改笔记标题内容 |
| 学科分支 | Select 分类属性；既有 Multi-select 可保留 | 作为数据库分类和看板分组的统一入口，不强行把多选压成单选 |
| 学科难度 | Select 单选 | 使用下表五档选项，保留已填写的判断，不随格式整理重新评级 |
| 学科层级 | Select 单选 | 支持一级、二级、三级、四级学科；已有五级、六级继续保留，缺失值不猜测填写 |
| 学习进度 | Number 数字，Percent 百分比格式 | 数字 AI 默认不调整；页面标题区以 Show as bar 进度条展示 |
 |
| 学科主题色 | Select 单选 | 按本页一级标题背景色选择对应的 Notion 颜色；所有视图与打开页面隐藏，供 AI 读取 |

### 学科主题色规则

- 选项为 `GRAY 灰色`、`BROWN 棕色`、`ORANGE 橙色`、`YELLOW 黄色`、`GREEN 绿色`、`BLUE 蓝色`、`PURPLE 紫色`、`PINK 粉色`、`RED 红色`，选项标签使用对应的 Notion 原生颜色
- 用户授权预填时，读取本页一级标题背景色；多种颜色先采用最前面的有背景色一级标题，并列入异常清单；没有一级标题背景色填 `DEFAULT 默认`，不借用二三级标题颜色
- 不使用 HEX 文本值；Notion 主题类别会随浅色和深色模式呈现不同实际色值
- 保留用户已有颜色值；AI 使用主题色制作视觉内容或整理笔记时，先读取该属性，只有授权改色时才覆盖
- Gallery、Board、Table 全部隐藏，不固定到标题，不在页面主区域或属性侧栏默认展示；在页面布局的属性可见性中设为“始终隐藏”，并应用到同库全部页面
- 隐藏不等于删除属性或限制访问；AI 仍可读取，用户仍可通过属性管理主动查看或编辑
- 该字段只保存配色参考，不自动改写封面、标题或正文颜色；没有色值时沿用现有配色

### 学习进度规则

- 使用原生 Number 属性，设置 Percent 格式
- 保留属性名 `学习进度`，由 Felix 自行判断与手动填写，AI 不动这个数字
- AI 默认只读并保留已有值；空白则初始化为 0，不重新估算、不自动补齐、不随正文优化、格式整理或数据库维护更新
- 只有用户明确要求修改 `学习进度` 时，AI 才按用户指定的值修改；一般的“优化笔记”或“整理数据库”不包含修改进度值的授权
- 合理填写范围为 0%–100%；空白与 0% 是不同状态，其含义由用户决定，不自动解释为正文尚空或学习尚未开始
- 在 Notion 界面输入带百分号的数值，例如 `50%`；底层数字为 0–1，API 写入 `0.5` 才是 50%，不能写入 `50` 后得到 5000%
- 打开页面时，在标题区显示该属性，并将 Show as 设置为 Bar（进度条）；显示百分比数值，沿用已有进度条颜色
- 工具支持时，配置对应为 `show_as.type = "bar"`、`show_as.maxValue = 1`、`show_as.showValue = true`；显示设置与记录数值分开维护，改为进度条不得改动任何记录的进度值
- Number 属性不会自动限制数值范围；验收时检查非空值是否在 0–1 内，超范围值先报告，不擅自覆盖
- 从旧 Select 字段转换前检查所有现有值；旧阶段标签不能直接推断为固定百分比，存在非空标签时先保留并讨论映射

`学习进度`与表示笔记建设状态的 `STATUS 状态`分开维护，不迁移、不覆盖其值。Gallery 和 Board 卡片不显示学习进度，Table 保留；打开页面标题区固定展示 `学科成绩 → 学习进度`，其中学习进度以 Bar 显示。
### 学科难度
| 学科难度选项（固定顺序） | Notion 颜色 |
|---|---|
| EASY 容易 | green 绿色 |
| BASIC 基础 | yellow 黄色 |
| MEDIUM 中等 | orange 橙色 |
| HARD 困难 | brown 棕色 |
| HELL 地狱 | red 红色 |

## 页面布局与属性可见性
- 需要查看其他属性时可使用属性侧栏。若用户要求在整个打开页面中隐藏某个属性，检查真正的属性可见性设置；仅移到侧栏不能算完全隐藏
- 未另指定时沿用已确认布局；不因管理数据库而自动把 Simple 改成 Tabbed 或反向转换

## 字段整合规则

- 旧 `Name`、`细分学科`、`哲学分支`等 Title 属性统一改名为 `学科名称`；先区分标题属性与分类属性
- 日常只使用 `学科难度`。整合旧难度字段时，先把非空值迁入标准字段并回读；两边值不同或选项不匹配时，保留并列出冲突，不能直接覆盖
- `领域`、`DOMAIN 领域`、`类型`、`Select`等字段只有在确实表达同一种分支分类时才整合到 `分支`；迁移已有值和有效分类选项后再清理旧字段
- 跨学科联系使用 `关联领域`，例如教育心理学与应用心理学的联系；它与分支分组不同
- 编程语言的通用语言等对象类别使用 `对象类型`；它与编程范式等分支不同
- `学科层级`的基础、核心、跨领域角色，与一级至四级的学科层级不同；前置知识关系、笔记状态也有独立用途，不自动合并
- 既有 `排序`字段可能驱动视图顺序，应先检查引用并保留其用途
- 标准学科数据库不新建 `Tags`、`Created/创建时间`或`导论`属性。用户已经明确批准清理目标范围内这些字段时可以删除；不把本技能当作跨任务删除其他库属性的授权
- 导论只放在笔记正文中。旧导论属性含有独有内容时，先保留到正文的导论位置；正文已完整覆盖其信息时，不重复追加
- 语言学的说明、编程语言的常见用途、相关机构等独立信息，不因为超出三个核心字段就自动删除

## 操作与验收

1. 读取连接工作区、目标父页、数据库 schema、视图、page layout 和现有记录，确认对象层级及用户授权范围
2. 分清只读验收、更新规范文件和执行 Notion 修改。分析或编辑 Skill 本身不授权批量修改 Notion
3. 优先复用原数据库与视图，保留记录 ID、子页面、正文、封面、媒体、关系及有效筛选和排序；不为了满足三视图顺序而删除重建旧视图
4. 属性迁移先复制、回读确认，再按授权删除旧字段；改名后核对视图、分组、排序和布局的属性引用
5. 回读实际配置和记录，对比条目数量、标题值、保留字段值及迁移值；分别检查 Gallery 卡片无非标题属性、两种卡片 Large/Page Cover、Full Page 打开方式和视图顺序
6. 接口未暴露 Card size、Page Cover、Full Page 或标签顺序设置时，使用已授权且可用的界面工具核实与设置；工具不可用则明确记录待完成项，不虚构参数或声称验收通过
7. 说明完成的写入、回读通过的项目以及仍需界面检查的项目；保存配置通过不等于桌面或移动端视觉验收通过

### 使用 Notion 工具时

- 先读当前工具 schema；需要配置视图时再读 `notion://docs/view-dsl-spec`，需要页面布局时再读 `notion://docs/database-page-layouts`
- `SHOW "学科名称"`可作为只显示标题的 Gallery 属性配置；非标题属性不得留在该卡片的显示列表中
- `Page Cover`指原生页面封面，不是一个名为 Page Cover 的属性；不能为套用 COVER 指令伪造文件属性
- 创建或更新看板时，保留 `GROUP BY "分支"`；表格 SHOW 顺序按核心字段表处理
- 工具未支持的打开方式、卡片大小或视图顺序，不通过未声明的参数猜测设置
- 单次批量修改采用可回读的小批次；遇到异步任务先等待成功再验证，遇到冲突只保留受影响项并继续其余已授权工作

本技能的正式源文件位于 Felix 工作流仓库的 `plugins/felix-workflows/skills/notion-academic-database-manager/SKILL.md`。可直接编辑 Markdown 并保存；不要维护安装缓存中的副本。界面名称与默认提示词在 `agents/openai.yaml`。

保存原件后，按本机支持的插件刷新或重新安装流程使新会话读取更新。其他设备需要同步仓库并刷新插件。不能承诺仅保存源文件就会热更新已经打开的对话。

# 学科笔记

主要维护 Felix 的 Notion 学科知识树；工作区显示名可能为 `Felix.Y 的个人空间` 或旧称 `Felix 的笔记本`，使用前仍须验证当前工作区身份。行业分类与研究使用 [行业笔记管家](../notion-industry-steward/SKILL.md)；公司正文、字段、品牌配色和模板使用 [公司笔记管家](../notion-company-steward/SKILL.md)。个人项目与日记格式保留在详细格式指南。

## 完整覆盖与完成标准

**默认要求：本次授权范围内的全部页面逐项验收，有缺口继续处理，最后列出实际未完成项；没有剩余也明确写“无”。用户无需重复提出。** 只读方案仍只读，指定章节仍限于该章；未验证项不得算作全部完成。

开始分析或优化前，必须读取[共同执行规则](references/completion-workflow.md)。默认检查用户指定的整篇或完整页面集合，建立覆盖清单，按内容质量补齐并持续执行到授权范围完成；分批写入不要求用户逐批说“继续”。只改某章、只整理格式或只要方案时遵守对应边界。

- “优化／执行”承接最近明确方案的交付对象；已授权的页面实施不退回另一轮建议，聊天提纲优化不自动变成 Notion 写入。
- 逐项记录已验证、无需改动、明确排除和受阻项；未读取不算已检查。事实与机制、例子与边界、资源保留及实际显示分别验收，不以新增标题或字数代替质量。
- 交付前核对全部承诺、章节清单与前后一致性；发现范围内缺陷继续修复，不把未完成事项包装成可选的下一步。真实工具障碍明确报告，并完成不受影响的工作。

## 维护入口

- **学科数据库的视图、卡片预览、页面打开方式与核心字段**：使用 [学科知识库管理规范](../notion-academic-database-manager/SKILL.md)
- **工作流程、通用格式和权限边界**：修改本文件
- **学科、个人项目与日记模板和参考页面**：修改[详细格式指南](references/format-guide.md)
- **技能列表中的显示名称、简介和默认提示词**：修改 `agents/openai.yaml`

本文件及参考文档以中文说明规则；英文工具名、配置键、页面字段和双语示例保持原名。下文的笔记标点规则用于生成的 Notion 正文，不要求维护者在 Skill 说明里也使用同样标点。

## 执行流程

1. **确认工作区与知识树**：通过 Notion `fetch` 工具传入 `{"id":"self"}`，以返回的工作区 ID 和目标页面的祖先路径判断归属，不用显示名做唯一判据。当前 Felix 工作区 ID 为 `f1b034c8-c79e-4bf2-97cf-d2522b18fa05`，显示名为 `Felix.Y 的个人空间`；`Felix 的笔记本` 是旧称。若 ID 变化，先核对目标是否仍位于 `ACADEMIC 知识树` 及其实际页面结构，再决定是否套用规范；不能仅因工作区改名而停止已授权的页面维护。
2. **确认任务范围**：查看、分析和提出建议属于只读任务。只有用户要求相应操作时，才新建、修改、移动、重命名或统一页面。
3. **先读后改**：读取目标页面或数据库结构；有相近页面时，检查两到三个同级页面。通用模板应让位于当前页面附近的实际结构与习惯；用户明确指定的规则优先。
4. **识别页面类型**：区分知识树、公司研究、个人项目和日记。新建、重排或检查格式时，读取[详细格式指南](references/format-guide.md)；公司研究读取 [公司笔记管家](../notion-company-steward/SKILL.md)。
5. **保留有效内容**：保留有意义的正文、关联、子页面、数据库、图片和属性。不能为了套模板而删除不符合模板的内容。
6. **控制修改范围**：只做实现目标所需的完整修改。未经明确授权，不批量统一历史页面、不纠正 `DAIRY` 等已有标签、不跨分支移动页面。
7. **复查结果**：修改后重新读取页面，核对标题、层级、属性、正文和子资源；流程图还需核对实际 Display 渲染与源码隐藏状态，Markdown 中存在图代码不等于显示模式已正确。说明已完成的修改及尚存的不一致。
8. **研究与引用**：需要核实事实时使用权威来源；除非用户明确要求，否则不向笔记正文添加 `References`、`Sources`、参考资料、书目或行内引用。

## 从指令识别修改范围

根据当前指令和此前已接受的方案判断范围，不要求用户每次选择模式。仅在歧义会改变页面身份、章节结构或共享数据时澄清；范围清楚且已获授权时直接完成。

| 范围 | 典型指令 | 行为 |
|---|---|---|
| 方案分析 | 优化方案、展示一下、分析这个提议 | 只读；提供具体替换文字或调整后的完整相关提纲，说明改动理由，不只列原则，不写入页面 |
| 内容完善 | 补充定义、完善内容、优化这篇笔记 | 在既有章节下补齐必要的定义、条件、例子和反例；默认保留章节名称、顺序与页面归属 |
| 排版整理 | 整理格式、优化双栏、统一标题颜色 | 在授权范围内调整样式、列表与布局，保留内容含义和章节名称；不为凑模板扩写正文 |
| 结构重整 | 重整章节、可以大改架构、移动到某分支 | 仅实施明确授权的结构调整；单篇正文重整不自动授权修改数据库或同级页面 |

- 这些范围可以组合；“章节命名不要改，其他执行”表示保留章节名，执行此前方案中其余已授权项，不重复询问。
- “开始”“执行”承接最近明确且可识别的方案。用户排除的章节、属性或资源持续排除，不因后续简短指令重新纳入。
- 修正事实错误不受“保留内容含义”限制，但须说明实质性纠错；跨篇迁移和共享属性变更仍按授权范围处理。
- 只有用户要求教学时才切换讲解流程；整理笔记不自动展开测验、学习路线或封面生成。

## 通用格式

### 章节架构与右侧辅助区

- 设计或优化章节时，采用简短、单一主题的标题，让每章职责清楚；将重叠内容归入最合适的章节，用关联连接相关知识，不反复讲解同一概念
- 章节数量与深度由内容决定，不机械扩充；简化架构时保留有效知识、例子与边界，不把简洁理解为删除必要解释。提出方案不等于获准改动页面
- 左侧承载完整理论、步骤、公式说明与适用边界；右侧只放对应的插图、短案例或例题，例子使用浅灰色 callout，不重复左侧正文，也不要求每节配图
- 右侧视觉素材优先考虑可靠的现成图片或适合的 ImageGen 插图，按知识点选择实物、界面对照、结构示意等；精确数值、几何或连接关系使用可核验的绘图工具，具体遵循 [学科插图](../academic-illustration/SKILL.md)
- 不默认用 Mermaid Flowchart 填充右侧。只有操作顺序、决策分支、状态转换或反馈循环明显更适合流程图时才使用，简单线性关系可直接用短文字表达
- 使用 Mermaid 或其他流程图时，笔记只展示渲染后的图，不展示源码。写入前确认目标能直接渲染；不能确认时先渲染为图片再嵌入，不能把代码块作为最终交付。修改后检查实际显示，API 返回源码不等于已经显示成图

### 学习进度的维护边界

- `学习进度`由 Felix 自行判断并手动调整；AI 默认只读，保留已有值与空白，不预估、不补齐，也不因正文优化或格式整理自动更新
- 只有用户明确要求修改该属性时，才按用户指定的值修改；修改笔记正文不等于获准修改学习进度
- 打开页面时，`学习进度`在标题区以 Show as bar 进度条显示，并保留百分比数值；调整显示方式不得改动进度值，具体配置见[学科知识库管理规范](../notion-academic-database-manager/SKILL.md#学习进度的手动维护与进度条显示)

### 学科父页的正文顺序

- 包含分支学科数据库的学科父页（如 `BUSINESS ADMINISTRATION 工商管理`），正文固定按 `INTRODUCTION → 分支学科数据库 → A、B、C 二级标题及内容` 排列。
- 第一行是未编号的 H1 `# INTRODUCTION 导论:`，沿用页面主题背景色；下一块紧接现有分支学科数据库，概述、定义或其他说明都放在数据库之后。
- 数据库之后使用 `## A. ...`、`## B. ...`、`## C. ...` 等蓝色二级标题，名称和数量按实际内容确定；不要把这些标题或正文插在 INTRODUCTION 与数据库之间。
- 保留现有数据库的身份、父子关系、视图和数据；重排时原样保留其原生数据库块，不另建重复数据库。具体示例见[学科父页模板](references/format-guide.md#学科父页模板)。
- 这项顺序规则适用于学科父页，不要求没有分支数据库的专题正文页新建数据库，也不改变公司研究或行业 Wiki 的专用架构。

### 页面名称与双语顺序

- 页面和数据库标题采用 `ENGLISH 中文`，英文在前、中文在后；英文部分全部大写。
- 英文或中文有通行简称时，优先用简称；没有时使用全称。不要把简称的展开形式堆入标题。
- 在 `Introduction → Overview → Definition` 对应的正文位置解释完整名称。
- 示例：`DS 数据科学`、`NLP 自然语言处理`、`MLOPS 模型运维`、`DATA ANALYSIS 数据分析`；正文中可解释为 `DS, Data Science 数据科学`。
- 其他双语标签在与同级页面习惯相符时，也采用英文在前、中文在后。
- 优先保留页面既有术语，不悄悄替换成另一种译法。

### 标题层级、大小写与颜色

| 层级 | 编号与示例 | 英文大小写 | 颜色 |
|---|---|---|---|
| H1 一级标题 | `# I. TOPIC 主题:` | 全部大写 | 文本背景色，使用本笔记的主题色 |
| H2 二级标题 | `## A. Topic 主题:` | 标题式大小写（Title Case） | 蓝色文字 |
| H3 三级标题 | `### a. Topic 主题:` | 标题式大小写（Title Case） | 橙色文字 |
| H4 四级标题 | `#### I. Topic 主题:`（大写罗马数字 I、II、III） | 标题式大小写（Title Case） | 黄色文字 |

- H2、H3、H4 使用标题式大小写（Title Case）：主要单词首字母大写；冠词、并列连词和介词（如 a、the、and、of、in、on）通常小写；标题首尾单词首字母大写。缩写、产品名和专有名词保留规范写法。
- 示例：`## A. US Domestic 美国国内`、`### a. Customer Segments 客户群体`。
- H2 蓝色文字、H3 橙色文字、H4 黄色文字是固定规则，除非用户明确对某个页面另作要求；这些是文字颜色，不是文本背景色。

### 学科简介不参与章节编号

- 学科笔记的 `INTRODUCTION 简介` 保持 H1 层级与本笔记主题背景色，但不加章号；第一个实质章节从 `I` 开始，后续连续编号。
- 示例：`# INTRODUCTION 简介:` → `# I. GROUP THEORY 群论:` → `# II. RING THEORY 环论:`。
- 新建学科笔记及授权整理标题编号时执行；只改某个段落时不借此重编号整篇历史笔记。用户明确说“INTRO 不算序号”时，调整该篇简介和后续章节编号，保留章节名。
- 公司、行业、项目和日记保留各自模板或用户指定规则，不把学科例外自动扩展到其他页面类型。

### 本笔记主题色的定义与选择顺序

- 一级标题使用文本背景色，颜色取本笔记的主题色，同一笔记的一级标题（包括简介）保持一致。
- **公司笔记**：主题色对应公司的品牌色。
- **学科笔记**：主题色对应这个学科的主题色。
- **优先级 1：本笔记已有定义**。已经定义或使用过主题色时，优先沿用，不因为重新查询品牌或看到相邻页面而擅自换色。
- **优先级 2：相邻同主题笔记**。本笔记没有定义时，从相邻笔记中查找同一公司、同一学科或明确适用于本主题的既有主题色；不能只因位置相邻就套用无关主题的颜色。
- **仍无依据时**：公司笔记可依据可靠的官方品牌资料确定颜色；学科笔记不臆造统一标准色，应向用户说明尚无定义并确认配色。其他类型沿用本笔记或相邻同主题笔记的既有定义。

### 第五层：有序列表与正文标点

- 一至四级标题的 Markdown 标记依次为 `#`、`##`、`###`、`####`，井号后加一个空格；井号数量与标题编号是两回事。
- 四级标题编号使用大写罗马数字 `I`、`II`、`III`，二级仍用大写字母 `A`、`B`、`C`，三级仍用小写字母 `a`、`b`、`c`。
- 第五层用真正的有序列表表达，不用 `#####` 标题。列表编号优先使用罗马数字，如 `i`、`ii`、`iii`；保留已有罗马数字列表。
- 只有当前编辑器或接口缺少罗马数字有序列表功能时，才回退到阿拉伯数字 `1`、`2`、`3`，并说明回退原因。不能以手写罗马数字的普通段落冒充真正的有序列表。
- 写入 Notion 时核实当前工具对四级标题及列表编号样式的支持；无法原样呈现四级标题时说明限制，不把降级格式报告为原生 H4。
- 每个新增编号条目先写**加粗的双语标签＋冒号**，再在同一列表块内换行写解释。
- 罗马数字样式示意：`i. **Definition 定义:**<br>解释内容`；功能不支持时使用 `1. **Definition 定义:**<br>解释内容`。示意中的罗马数字不是通用 Markdown 列表语法，实际需要设置有序列表编号样式。标签与说明必须处于同一个编号列表块。
- 新写的笔记正文用半角逗号 `,`，不用中文逗号 `，`；逗号后还有下一短语时加一个普通空格。
- 普通段落和解释性列表项的末尾不加 `。` 或 `.`。
- 代码、URL、引文、缩写、数据值和其他需要原样保留的内容，其必要标点不得删除。

### 学科笔记的正文与说明区

- 左侧正文区承载学科知识主线，例如概念、定义、公式、推导、性质和方法；右侧说明区可放例子、例题、计算、图示、用于讲解程序本身的代码和学习问题；流程图源码不属于阅读区代码示例。
- **学科联系放在右侧折叠列表**：`Connections 学科联系` 使用原生 Toggle List，放在相关正文的右侧说明区；折叠标签采用加粗双语名称，不作为左侧正文或双栏外的编号章节，也不用 Toggle Heading 代替。展开后保留学科关联说明与原生页面引用；具体结构见[格式指南](references/format-guide.md#学科联系折叠列表)。仅在本次授权范围内新建或调整，不因技能更新批量迁移历史页面。
- **一级标题始终在双栏外**：包括 `INTRODUCTION` 在内的全部 H1 独立占据整行，不放入任何左栏或右栏。章节编号、名称、顺序与主题背景色保持不变。
- **二至五级内容灵活进入双栏**：H2、H3、H4 与第五层有序列表可以位于左侧正文栏，也可以在双栏外承接正文；按两侧实际长度选择从哪一级开始或结束双栏，不固定每个 H2 或 H3 都创建一组双栏。第五层仍是有序列表，不创建 `#####` 标题。右侧例子使用加粗双语标签，不占用正文的章节编号。
- **双栏默认左 60% / 右 40%**：用户指定其他比例时采用用户比例；右侧没有实质辅助内容时可保持单栏。图、表、公式与 callout 的高度均计入两侧布局判断。
- **长度与对应关系允许适度宽限**：优先让辅助内容靠近相关正文，但不要求逐段、逐条严格对应；为平衡两侧长度，可以让同一一级章节内邻近主题的例子或插图适度错位，保留明确标签以避免误配。不要把不相关内容或另一章的辅助内容搬来凑齐。
- **约 5 行为默认对齐宽限**：按当前栏宽下实际显示的文本行高估算，两侧底部相差约 5 行以内通常可以接受，不为消除这点差距拆碎内容或插入空白。明显超过宽限时，优先在完整段落、例子或较低层级小节的边界拆分、合并双栏或调整辅助内容位置。5 行是视觉参考，不是源 Markdown 行数或硬性等高要求；无法查看实际渲染时说明仅按内容长度估算。
- **部分例子可用浅灰色 callout**：短例子、手算与易错提醒可使用 `gray_bg`；较宽的表格和插图直接放在右栏，不要求所有辅助内容都包入 callout。不为对齐删减有效知识、扩写无关文字、压缩字号或添加占位资源。
- **默认不添加学习路线类内容**，包括学习顺序、学习路径、学习建议、复习路线或类似的导航性小节。不要为了凑齐章节而新建这类内容。
- 只有学习路线确实能帮助理解当前知识结构，且页面有合适的右侧说明区时，才将其作为简短辅助说明放在右侧；不要将它设为左侧正文区的章节、学习主线或必备模板项。
- 没有合适的右侧说明区时，省略学习路线，不为它单独创建空白双栏。已有页面中的相关内容先按任务范围和保留有效内容原则处理，不因本规则自动批量删除或迁移。

### 流程图显示：只展示 Display

- **所有流程图只展示渲染图**：学科笔记正文、右侧说明区、callout、折叠区及交付预览中的 flowchart 默认只显示 `Display` 图，不显示 `Code` 源码，也不使用图与代码并排的模式。Mermaid 的 `flowchart` / `graph`、状态图、时序图等图示均采用这一展示规则。
- **源码用于制作，不作为交付内容**：允许内部使用 Mermaid 或其他图形源码生成图；写入原生 Mermaid 块时选择 `Display`，不额外复制源码到正文、callout、折叠区、代码附件或回复中。展示规则不影响 HDL、Python 等用于解释程序本身的代码示例；用户明确要求查看或编辑图源码时按该次要求处理。
- **按真实能力设置模式**：先核实当前工具是否支持图块显示模式；支持时设置为 `Display`。接口仅支持 Markdown 或源码写入时，不编造显示属性，不把 `mermaid` 语言标记当作已隐藏源码；可用编辑器 UI 时切换到 `Display` 并核对实际图形。界面可能将同一模式标为 `Preview` 或 “Show only preview and hide code”；以实际仅显示图形、隐藏源码的行为为准。
- **无法设置模式时使用渲染图**：优先交付或嵌入已渲染的图像，确认节点、箭头、标签与原图一致且清晰；不要为了隐藏源码直接删除图或用空白占位。保留已有资源和必要的可编辑来源，不在阅读区重复展示源码；无法渲染或验证时准确说明尚未完成的显示检查。
- **检查所有可能露出源码的位置**：本次授权页面中的正文、双栏、callout、折叠区和嵌套块，以及方案预览、最终回复和附件均需检查；避免同一图以渲染图与原始代码重复出现。整页替换、复制图块或重新写入 Mermaid 后必须再次检查显示模式，不能假定原先的 Display 设置会被继承；切换后重新读取实际界面，确认图形仍在且源码不可见。此次技能更新不自动授权批量修改历史笔记。

# Felix 的笔记本：详细格式指南

本指南以 2026-08-20 观察到的习惯为基础，持续维护。使用时仍需检查当前同级页面，不应仅凭旧模板覆盖已有的明确结构。

## 通用格式速查

主文件 `SKILL.md` 维护通用规则；本节便于对照模板。修改标题、编号或标点规则时，应同步检查主文件，避免冲突。

| 项目 | 规则 |
|---|---|
| 页面与数据库名称 | `ENGLISH 中文`，英文全部大写；有通行简称时优先简称，否则用全称 |
| 全称解释 | 放在 `Introduction → Overview → Definition`，不堆入标题 |
| 名称示例 | `DS 数据科学`、`AI 人工智能`、`NLP 自然语言处理`、`MLOPS 模型运维`、`DATA ANALYSIS 数据分析` |
| 图标 | 同级页面使用 emoji 时，选择与分类相关的 emoji |
| 双语顺序 | 英文在前，中文在后 |
| H1（一个井号 `#`） | 大写罗马数字编号，如 `# I. TOPIC 主题:`；英文全大写；文本背景色使用本笔记主题色 |
| H2（两个井号 `##`） | 大写字母编号，如 `## A. Topic 主题:`；英文采用标题式大小写（Title Case）；蓝色文字 |
| H3（三个井号 `###`） | 小写字母编号，如 `### a. Topic 主题:`；英文采用标题式大小写（Title Case）；橙色文字 |
| H4（四个井号 `####`） | 大写罗马数字编号，如 `#### I. Topic 主题:`；英文采用标题式大小写（Title Case）；黄色文字 |
| 第五层（有序列表，不用 `#####`） | 优先使用真正的罗马数字有序列表，如 i、ii、iii；仅在编辑器或接口缺少该功能时回退到阿拉伯数字 1、2、3；保留已有罗马数字列表 |
| 新增列表项 | 罗马数字样式示意 `i. **Label 标签:**<br>解释内容`；功能不支持时用 `1. **Label 标签:**<br>解释内容`，标签与解释放在同一编号列表块中 |
| 逗号 | 新写的笔记正文用半角 `,`，后续还有短语时加一个空格 |
| 句末标点 | 普通段落和解释性列表项末尾不加 `。` 或 `.`；保留代码、URL、引文、缩写、数据值和字面名称中的必要标点 |
| 引用 | 默认不添加参考资料、来源章节或行内引用，用户明确要求时才加入 |

H2、H3、H4 采用标题式大小写（Title Case）：主要单词（名词、代词、动词、形容词、副词等）首字母大写；冠词、并列连词和介词通常小写，如 `a`、`an`、`the`、`and`、`or`、`but`、`of`、`in`、`on`、`for`、`with`。标题首尾单词首字母大写；`US`、`AI`、`DHL`、`iPhone`、`eCommerce` 等缩写、产品名和专有名词保留规范写法。

示例：`Customer Segments and Value Creation`、`Applications of AI in Business`。

简介通常对应 H1 `INTRODUCTION 简介`、H2 `Overview 概述`、H3 `Definition 定义`。标题和加粗标签通常以冒号结尾；历史页面写法不一致时，保留局部习惯。

H2 蓝色文字、H3 橙色文字、H4 黄色文字。H1 使用文本背景色，取本笔记主题色。

**主题色定义**：公司笔记对应品牌色，学科笔记对应本学科主题色。先沿用本笔记已经定义或使用过的主题色；没有时，再从相邻笔记中查找同一公司、同一学科或明确适用于本主题的已有配色。不套用仅在位置上相邻、主题却无关的颜色。具体优先级以主文件“本笔记主题色的定义与选择顺序”为准。

## 五层结构示意

井号后加一个空格。标题编号依次使用 `I → A → a → I`，第五层为有序列表。

```text
# I. TOPIC 主题:
## A. Main Topic 主要主题:
### a. Subtopic 子主题:
#### I. Detailed Topic 细分主题:
i. **Definition 定义:**<br>解释内容
ii. **Example 示例:**<br>示例内容
```

这里的 `i.`、`ii.` 只表示期望的列表显示样式，不是通用 Markdown 有序列表语法。应创建真正的有序列表并设置罗马数字样式；只有当前工具缺少该功能时，才用 `1.`、`2.` 回退，并说明原因，不用普通段落手写编号冒充列表。

写入 Notion 时核实四级标题的实际支持情况；无法原样呈现时说明限制，不把降级格式报告为原生 H4。下方旧结构示例中的阿拉伯数字列表仅作为功能缺失时的回退示例。

## 知识树页面

适用于学科、软件概念、工具和编程语言。

以下保留原始结构示例，便于识别历史页面。新写内容的大小写、配色和列表标签仍按上方规则执行；例如新 H1 使用全大写英文，新列表项加粗标签并在块内换行。

```text
# Introduction 简介:
## A. Overview 概述:
### a. Definition 定义:
1. **Definition 定义:**
### b. Origin/Objectives 起源/目标:

# I. First Domain 第一部分:
## A. Subtopic 子主题:
### a. Concept 概念:
1. **Term 术语:**
```

页面本身是分类节点时，可在简介附近放置内嵌分支数据库。不要仅为了外观一致而新建数据库。

## 公司研究页面

适用于公司、企业集团和行业参与者。

### 数据库字段

| 字段名（保留原名） | 要求 |
|---|---|
| `COMPANY 企业` | 标题属性 |
| `WEBSITE 官网` | URL 属性，使用公司官方企业主页 |
| `INDUSTRY 行业` | 以实际数据库结构为准 |
| `DOMAIN 领域` | 默认视图隐藏，保留字段 |
| `HEADQUARTERS 总部` | 国家或地区＋都市圈 |
| `FOUNDED 成立` | 默认视图隐藏，保留字段 |
| `FOUNDER 创始人` | 以实际数据库结构为准 |
| `LEADER 领导人` | 默认视图隐藏，保留字段 |
| `OWNERSHIP 所有制` | 默认视图隐藏，保留字段 |
| `PRODUCTS 产品` | 以实际数据库结构为准 |
| `DESCRIPTION 简介` | 以实际数据库结构为准 |
| `TITLE 称号` | 以实际数据库结构为准 |

**总部格式**：例如 `美国湾区`、`美国洛杉矶`、`中国上海`。不要只填城市、街道或办公楼地址。经营中心跨越多个行政区时，优先使用通行都市圈名称。

**隐藏与删除不同**：默认视图隐藏的四个字段仍保留在数据库结构中；需要时可在比较、治理或研究完整性视图里显示。

**复用历史字段**：历史数据库已有名称不同但含义相同的属性时，单页修改应复用。未经数据库整体迁移授权，不重命名共享属性，也不新建重复属性。

**官网字段**：使用公司官方企业主页，不用产品页、新闻、社交账号或第三方资料页代替。表格视图保留此属性；画廊或看板中若显得杂乱，可以隐藏。添加属性本身不代表获得批量研究和补全缺失网址的授权。

### 公司品牌配色

- 公司页面全部 H1 使用本笔记主题色作为文本背景色，包括简介、业务板块、商业模式、组织与经营。
- 先用本笔记已定义或使用过的主题色；没有时，从相邻同公司或明确适用于本主题的笔记中查找已有定义。以下品牌取色规则仅在两处均无定义、需要新确定颜色时使用。
- 颜色依据母公司官方视觉形象、企业 Logo 或公开品牌规范，不从产品线、临时活动、封面图、管理者照片或第三方设计推断。
- 多品牌控股集团默认使用母集团企业色，除非页面明确研究的是某个子公司。
- 映射到最接近的 Notion 预设背景色：`red_bg`、`orange_bg`、`yellow_bg`、`green_bg`、`blue_bg`、`purple_bg`、`pink_bg`、`brown_bg`、`gray_bg`。
- 保证可读性。官方配色为黑、白、金属色或其他不受支持的颜色时，使用 `gray_bg` 或最接近且可辨认的企业强调色。
- 缺乏可靠品牌依据，且本笔记与相邻同主题笔记都无配色定义时，说明缺少依据并确认颜色；不直接沿用无关公司或行业分类色。
- 不为配合主题色而更改固定文字颜色：H2 蓝色、H3 橙色、H4 黄色。

### 建议正文结构

这是章节结构示例。实际新增列表项应使用加粗双语标签、块内换行与真正的 Notion 编号列表；`NOTE_THEME_COLOR_bg` 需要替换为实际预设背景色。

```text
# I. INTRODUCTION 简介: {color="NOTE_THEME_COLOR_bg"}

### a. Definition 定义:
1. Definition 定义:
2. Position 定位:
### b. Development 发展:
1. Foundation 创立:
2. Milestones 里程碑:
3. Current Stage 当前阶段:

# II. BUSINESS SEGMENTS 业务板块: {color="NOTE_THEME_COLOR_bg"}
## A. First Segment 第一板块:
## B. Second Segment 第二板块:

# III. BUSINESS MODEL 商业模式: {color="NOTE_THEME_COLOR_bg"}
## A. Customers 客户:
### a. Customer Segments 客户群体:
## B. Revenue Model 收入模式:
### a. Revenue Sources 收入来源:
## C. Value Chain 价值链:
```

## 个人项目页面

适用于业务、转型计划和持续推进的个人项目。保留通用层级，同时允许执行事项、内嵌数据库、进度记录和按时间更新的内容。现有页面支持时，将稳定的项目介绍与持续变化的计划分开。

参考页面：

- HARVESTFLOW 德馨淼盛：`222ab59a-584f-802e-b890-fb2a58f47cf8`

## 日记页面

日记允许更灵活的结构。保留按时间、季度、课程或地点组织的方式，不强套知识树的简介模板。只有编号有助于导航时，才使用带编号的 H1。

参考页面：

- Journal of Davis 戴维斯日记：`312ab59a-584f-8016-9d3a-f866146518ef`

## 历史差异：不要静默统一

- `DAIRY 日记` 可能是有意命名或历史标签，即使通常拼作 `DIARY`，也不要擅自改动。
- 用户未要求重命名页面或分支时，可保留历史大小写。新增标题或受托统一标题时，执行英文大写、简称优先、双语命名规则。
- `Introduction 简介`、`Introduction 导论`、大小写、加粗和末尾冒号存在差异。
- 部分页面重复小节字母，或混用纯中文与双语标题。
- 不同行业分支的公司数据库结构存在差异。

用户要求统一时，先列出限定范围的修改清单，区分错字修正、视觉格式统一、数据库结构变更与页面移动。
